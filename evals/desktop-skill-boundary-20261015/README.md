# Desktop 관측 한계와 CLI 암묵 선택 보충

기준일: 2026-10-15. 기준 커밋: `bb112e8a2a13e47ca343b73d56b4f83a6ec58648`.

**Desktop 스킬 선택기와 Desktop 암묵 선택은 미검증이다.** 직접 관측 도구가 초기화 전에 실패해 앱 목록·선택기·입력·스크린샷을 얻지 못했다. 이 실패를 Desktop 제품 결함이나 스킬 오작동으로 판정하지 않는다. 현재 가능한 CLI 암묵 선택만 임시 프로젝트에서 보충했고, 둘을 합쳐 Desktop 통과로 보고하지 않는다. 앱 설치·제품 개발·환경 복구는 수행하지 않았다.

## Desktop에서 확인한 것과 못한 것

`computer-use` 스킬의 지정 경로인 `node_repl`에서 `@oai/sky` 초기화를 한 번 요청했다. 반환 오류는 다음과 같다.

```text
failed to write kernel assets: 지정된 경로를 찾을 수 없습니다. (os error 3)
```

이는 앱 열거·캡처·입력 이전의 도구 초기화 실패다. 패키지 자체가 없거나 Desktop이 고장났다고 원인을 확정하지 않는다. `computer-use`가 요구하는 관측된 윈도우·포커스를 확보할 수 없어 UI 조작을 진행하지 않았다. 다른 UI 자동화·내부 디버거·직접 helper 호출로 우회하지 않았고, 설치·재시작·ACL/설정 변경·도구 복구도 추가하지 않았다.

이 세션의 브라우저 제어 도구는 네이티브 컴퓨터 API 비활성으로 안내돼 있으며 Desktop 선택기 대체 관측으로 쓰지 않았다. 별도 앱 화면 컨텍스트 도구는 활성 음성 대화에서만 허용되므로 이 텍스트 대화에서 호출하지 않았다. 스레드/브라우저 관리 도구에는 스킬 선택기의 항목·선택된 칩을 읽는 API가 없어 UI 관측을 대체하지 못한다.

따라서 Desktop에서 동명 항목이 몇 개 보이는지, 경로/스코프가 표시되는지, 어떤 항목이 선택됐는지, 제출 뒤 어떤 스킬을 읽는지, 이름을 주지 않은 새 요청에 무엇이 선택되는지는 **전부 미관측**이다. Desktop 앱 버전도 이번에 별도 확인하지 않았다. 새 Desktop 작업을 제출하거나 임시 프로젝트를 앱에 등록하지 않았다.

## 가능한 CLI 보충 시험

기존 **Codex CLI `0.162.0-alpha.17.2`, Windows**를 사용했다. 임시 Git 루트와 하위 폴더에 두 스킬의 복사본을 두고, 개인 설치본은 유지했다. 루트·하위본은 기존 `name`, `description`, 본문을 유지하되 끝에 서로 다른 읽기 영수증만 붙였다. 명시 전용 설정이나 UI 메타데이터는 추가하지 않았다. [시험 구성](fixture-spec.md)에 경로·입력·범위를 기록했다.

먼저 기존 [읽기 전용 catalog 클라이언트](../codex-skill-discovery-20261015/catalog-probe.mjs)를 그대로 재사용해 `skills/list`, `forceReload: true`를 호출했다. 전체 30개가 반환됐으며 두 원래 스킬은 각각 루트·하위·개인본이 `enabled: true`로 함께 검색됐다. 나머지 세 스킬은 개인본만 검색됐다. 오류 목록은 비어 있었다. [현재 CLI 목록](cli-catalog.json)은 다섯 대상만 필터링하고 개인 경로를 익명화한 실제 응답이며 Desktop UI 목록은 아니다.

별도의 비영속 `exec --ephemeral --json --sandbox read-only`, `--no-daemon`, 승인 `never`, 하위 CWD로 세 번 실행했다. 모델·추론 설정을 따로 지정하지 않았으며 실제 해결 모델 ID를 이벤트에서 별도 확인하지 않았다. 요청에는 **스킬 이름·경로·호출 지시·표식 힌트가 없었다.** 작업별 새 turn을 사용했고 기존 대화의 답이나 기대 선택을 주지 않았다.

| 사례 | 자연어 요청 | 실제 관측 |
| --- | --- | --- |
| I1 양성 | 메모 응답 유실·인증 만료의 발생/보존/복구/해제 명세, 정책 미정 | 하위 `specify-failure-recovery/SKILL.md`만 읽고 해당 영수증 출력 |
| I2 양성 | A 실사용 PASS·B 모의 PASS·B 제한 인계 승인과 전달 증거 공백 판정 | 하위 `review-release-evidence/SKILL.md`만 읽고 해당 영수증 출력 |
| I0 음성 | “9 더하기 7”, 숫자 하나만 답변 | 답 `16`, 도구 실행과 대상 스킬 파일 읽기 관측 없음 |

세 turn 모두 완료됐고, 양성 두 건의 `command_execution`에서 `Get-Content` 경로·스킬 본문·종료코드 0을 확인했다. 최종 표식만으로 읽기를 추정하지 않았다. 보이는 모델 도구 호출은 두 파일 읽기뿐이었다. I1에서 릴리즈 검토를, I2에서 오류 명세 스킬을 추가로 읽지 않았다. 이 표본에서는 기대한 경계와 일치했지만 일반적인 자동 호출률·정확도·Skill 효과·고정 우선순위의 증명은 아니다.

[관측 기록](observations.json)에는 정확한 요청, 필터링한 완료 이벤트, 최종 답변, Desktop 초기화 오류와 보호 파일 해시를 함께 남겼다. 원시 trace 전체가 아니며 세션 ID·개인 절대 경로·인증정보·기존 스킬 본문 복제본은 게시하지 않았다. 답변은 합성 문서 시험 결과이지 승인된 제품 명세나 실제 전달·배포 결과가 아니다.

## 이전 CLI 결과와 Desktop의 비교

| 항목 | 이전 CLI 명시 시험 | 이번 CLI 보충 | Desktop |
| --- | --- | --- | --- |
| 검색 | 다섯 이름 모두 개인·루트·하위본 공존 | 두 이름은 세 본 공존, 다른 세 이름은 개인본만 | 선택기 항목·정렬·경로 표시는 미관측 |
| 이름 지정 | 다섯 이름 모두 해당 표본에서 하위본 읽음 | 이름을 지정하지 않음 | 선택기 클릭·제출 미실시 |
| 경로 지정 | 개인본 정확한 경로 지정 시 개인본 읽음 | 반복하지 않음 | 칩/입력이 전달한 경로 미관측 |
| 암묵 선택 | 당시 미검증 | 두 양성은 해당 하위본 읽음, 산술 음성은 대상 읽기 없음 | 새 요청 제출·선택 근거 미관측 |
| 설정 보존 | 패키지·설정 11개 해시 동일 | 같은 11개 전후 해시 동일 | UI/설정 변경 없음. PC 전체 무변화 감사는 아님 |

**Desktop과 CLI가 같거나 다르다는 동작 판정은 불가능하다.** 확인된 차이는 관측 가능한 표면과 증거의 차이뿐이다. 이전 CLI 명시 시험은 탐침 전용 description·본문을 썼고 이번에는 원래 description·본문을 유지했으므로, 두 결과도 입력 방식 하나만 바꾼 통제된 A/B가 아니다. CLI 반환 순서나 이번 하위본 읽기를 Desktop 선택기 정렬/우선순위로 전용하지 않는다.

## 보존·종료와 선택적 재개

기존 다섯 패키지 9개 파일과 사용자 `config.toml`·빈 사용자 `AGENTS.md`, 총 11개 파일의 SHA-256을 전후 비교해 변경 0개를 확인했다. 기존 제품 프로젝트와 실제 설치본을 수정하지 않았다. 스킬 본문·description·템플릿·전역 암묵 호출 정책의 결함을 이번 관측으로 입증하지 못했으므로 배포 규칙은 추가하지 않는다. 평가 문서와 안내 링크만 보완한다.

Codex 모델 요청과 GitHub 게시에는 정상 서비스 통신을 사용했다. 프롬프트의 외부 도구 제한은 오프라인 추론을 뜻하지 않는다. `--ephemeral`도 정상적인 로그·캐시까지 전혀 쓰지 않는다는 뜻은 아니며 PC 전체 무변화를 주장하지 않는다.

현재 범위는 이 관측 한계와 CLI 대조 인계로 종료한다. UI 관측이 없는 상태에서 같은 초기화를 반복하거나 새 앱·플러그인을 설치하지 않는다. 현재 PC에서 허용된 직접 UI 관측 또는 사용자가 제공한 관측이 생겼을 때만 선택적으로 재개한다. 새 장비·다른 PC·앱 설치를 요구하지 않는다.

재개 시에는 같은 임시 CWD를 사용하고, 다른 대화의 선택 이력이 없는 요청으로 선택기 이름 검색 → 각 항목의 표시·경로/스코프 → 선택된 칩과 실제 읽은 파일을 연결해 기록한다. 암묵 선택은 선택기를 고르지 않고 이 문서의 I1/I2/I0 요청을 각각 새 컨텍스트에서 비교한다. 관측할 수 없는 경로는 미확인으로 남기며 자동으로 가까운 본이라고 정하지 않는다. 이 후속 UI 시험은 이번 완료 조건이 아니다.
