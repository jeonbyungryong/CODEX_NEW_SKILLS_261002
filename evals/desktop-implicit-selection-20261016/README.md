## 1. 실행 조건과 실제 작업 폴더

- 사용자 요청: 등록 완료 후 nested 여부를 확인하고, 확인되면 I1·I2·I0만 각각 새 대화에서 실행. 기존 설치본·설정은 변경하지 않음.
- `list_projects`에서 이름 `nested`인 로컬 프로젝트가 반환됐고, 경로가 준비한 `TEMP/repo/nested`와 정확히 일치했다. 프로젝트 이름만으로 고르지 않았다.
- 공개 별칭 `TEMP`는 준비 폴더, `ROOT`는 그 아래 repo, `NESTED`는 repo/nested, `USER`는 기존 개인 설치 영역이다. 개인 절대경로와 ID는 공개하지 않는다.
- `create_thread`에 반환된 projectId와 local 환경을 사용했다. worktree·cloud·projectless로 대체하거나 모델/추론 수준을 지정하지 않았다. 실제 모델·추론 값은 사용한 조회 메타데이터에 노출되지 않아 미확인이다.
- 확인용 새 대화에서 `(Get-Location).Path`가 exit 0으로 NESTED를 출력했다. `read_thread.thread.cwd`, 해당 commandExecution.cwd와 출력이 일치했다. 자기 보고만을 근거로 삼지 않았다.
- 이후 시험은 확인용 대화를 계속하거나 fork하지 않고 각각 새로 생성했다. I1·I2의 실제 읽기 명령 cwd도 NESTED다. I0는 셸을 실행하지 않았으므로 그 사례의 셸 출력은 없고, 전용 도구가 반환한 대화 cwd로 확인했다.
- 등록 목록의 isGitRepository는 false였지만 이를 CWD나 Git 경계 판정으로 대체하지 않았다. 준비 기록의 repo Git 경계와 프로젝트 메타데이터는 별개다.

공식 안내의 primary 폴더 설명은 출발점 참고이며, 이번에는 실제 대화 CWD와 실행 결과를 별도로 확인했다. [Projects and chats](https://learn.chatgpt.com/docs/projects), 확인 2026-10-16.

## 2. 입력과 관측 방법

각 최초 요청은 [수동 안내](../../docs/desktop-manual-skill-check.md)의 I1·I2·I0 원문과 일치했다. 스킬명·경로·기대 표식·정답표·준비 문서·추가 지시를 붙이지 않았다. 제목은 일반 업무 주제였고 대상 스킬명을 넣지 않았다.

전용 도구는 새 대화에 `codex_delegation` wrapper와 source_thread_id를 붙여 전달했다. 따라서 사람이 입력창에 직접 입력한 경로와 전송 형식까지 같다고 주장하지 않는다. 반환된 첫 턴에서 input 본문은 원문 그대로였으며 부모 대화나 안내문을 추가로 읽은 이벤트는 관측되지 않았다. 보이지 않는 내부 컨텍스트까지 무오염이라고 증명한 것은 아니다.

`wait_threads`로 완료를 기다리고 `read_thread(includeOutputs=true)`로 이미 생성된 첫 턴의 실행 기록·최종 응답을 읽었다. 새 메시지로 “어떤 스킬을 썼나”를 묻거나 경로를 지정해 재선택시키지 않았다. 시험 재실행과 후속 요청은 0회다.

초기 기록 조회에서 maxOutputCharsPerItem=30000은 도구가 허용하는 상한 20000을 넘어 거부됐다. 조회 한도를 20000으로 바꿔 성공했으며, 시험 대화에 추가 요청을 보내거나 시험을 다시 실행한 것은 아니다. 공개 근거에 사용한 명령 출력은 truncated=false였다.

## 3. 읽기와 답변의 구분

### I1 — 오류·복구 명세

첫 턴의 명령 1개가 `NESTED/.agents/skills/specify-failure-recovery/SKILL.md`를 읽었고 종료 코드는 0이었다. 읽힌 본문과 최종 답변에서 `READ_RECEIPT_NESTED_specify-failure-recovery`를 확인했다.

답변은 응답 유실을 저장 실패 확정과 구분하고, 요청 당시 입력·후속 편집·마지막 확인 저장본을 보존하도록 작성했다. 인증 해제와 저장 오류 해제, 상태 갱신 사건을 분리했다. 자동 재시도 수치·인증 만료 후 편집 정책·결정 담당자는 미정으로 유지했다.

기본 내용은 요청과 부합했지만 “짧게” 요청에 비해 표와 상세 문장이 길었다. 이번에는 길이 선호를 선택 실패나 스킬 과잉 호출로 합치지 않고 출력 분량 관찰로 남긴다. 제품 구현·실제 복구·일반적인 명세 완전성은 시험하지 않았다.

### I2 — 후보별 인계 근거

첫 턴의 명령 1개가 `NESTED/.agents/skills/review-release-evidence/SKILL.md`를 읽었고 종료 코드는 0이었다. 읽힌 본문과 최종 답변에서 `READ_RECEIPT_NESTED_review-release-evidence`를 확인했다.

답변은 6문장과 별도 읽기 표식이었다. B의 제한 운영 인계 승인·의사결정 완료만 인정하고 실제 전달·배포 완료는 인정하지 않았다. A 실사용 PASS와 B 모의 PASS를 합치지 않았고, B의 정확한 버전·전달 증거·담당/시점을 공백으로 남겼다. 위험 수용으로 승인된 결정을 자동 재개하지도 않았다.

### I0 — 산술 음성 대조

최종 답변은 숫자 `16` 하나였다. 반환된 첫 턴에는 생성 도구의 입력 wrapper, 비공개 추론의 빈 표시, 최종 응답만 있었고 commandExecution은 0개였다. 대상 다섯 스킬 파일의 읽기 이벤트나 표식은 관측되지 않았다.

이 관측은 숨겨진 본문 주입이나 내부 선택이 전혀 없었다는 증명이 아니다. 답을 맞췄다는 사실만으로 음성 대조의 모든 내부 동작을 PASS라고 하지 않는다.

최초 입력·관측 명령의 공개 별칭·최종 답변은 [비식별 근거](evidence.json)에 있다. 명령 경로는 별칭으로 바꾼 요약이며 원시 trace가 아니다.

## 5. 종료 범위

승인된 I1·I2·I0를 한 번씩 관측했으므로 종료한다. 관련 없는 스킬 적용, 추가 I3~I5, 선택기 자동 조작·앱 복구·설치로 확대하지 않는다. 두 양성에서 기대한 NESTED 파일을 읽은 것이 관측됐고 I0에서 불필요한 파일 읽기는 보이지 않아, 이 세 사례만으로 배포 스킬 본문을 고칠 근거는 발견하지 못했다. 반복 안정성·스킬의 추가 효과·다른 PC 및 모델·직접 UI 입력/선택기는 미검증으로 남긴다.

## 6. 별도 승인 후 I3·I4·I5 확장 실측

최초 세 사례 종료 후 사용자가 같은 임시 프로젝트의 나머지 세 스킬도 각각 새 대화에서 시험하도록 별도로 요청했다. 기존 시험 대화는 계속하거나 fork하지 않았고, I3·I4·I5 원문만 새 로컬 대화 3개에 각각 제출했다. 이 추가 요청이 없었다면 선택 확장을 실행하지 않았을 것이다.

### 작업 폴더와 읽기 근거

`list_projects`에서 준비한 nested 절대경로와 일치하는 로컬 프로젝트를 다시 확인했다. 각 시험의 `read_thread.thread.cwd`와 모든 commandExecution.cwd도 그 경로와 일치했다. 실제 실행 명령의 cwd를 확인했으며, 단순한 스킬의 자기 보고로 채점하지 않았다. 새 Get-Location 요청을 시험 턴에 추가하지 않았다.

| 사례 | 첫 턴에서 실제 읽은 NESTED 패키지 파일 | 읽기 결과·최종 응답 |
| --- | --- | --- |
| I3 | `coordinate-device-validation/SKILL.md`, `references/timing-budget.md` | 두 읽기 모두 exit 0, `READ_RECEIPT_NESTED_coordinate-device-validation` |
| I4 | `verify-powershell-handoff/SKILL.md` | 읽기 exit 0, `READ_RECEIPT_NESTED_verify-powershell-handoff`; 아래 실행 금지 충돌 별도 |
| I5 | `diagnose-computer-use-recovery/SKILL.md` | 읽기 exit 0, `READ_RECEIPT_NESTED_diagnose-computer-use-recovery` |

세 사례 모두 **PATH_READ_OBSERVED + BODY_OBSERVED**다. 지침 파일을 읽은 명령은 `pwsh.exe -Command Get-Content -LiteralPath ...` 형태였으며 command 출력은 truncated=false였다. I3의 추가 시간 예산 참조 읽기는 본문이 시간 제한 요청에서 요구하는 관련 참조 읽기다. 첫 턴의 표시된 명령 4개는 이 문서 열람뿐이었고, 다른 스킬·helper·기기·실제 로그를 다루는 실행 이벤트는 관측되지 않았다.

### 답변 내용과 실행 경계

- **I3:** 4초+4초의 순차 합계 8초가 5초 관측창을 넘는다고 판단했다. 이미 창 밖에 있는 준비를 또 옮겨 시간을 절약한다고 하지 않았다. 창 연장, 주입 시점 변경, 실제 단계 단축은 각각 조건과 달라지는 증명 범위를 붙였다. 기기·복구 성공을 검증한 결과라고 하지 않았고 기기 조작이나 수집기 개발은 없었다.
- **I4:** PowerShell 7의 성공 보고와 수신자 5.1 검증을 구분하고 준비 완료 판정을 보류했다. 3건 Count·항목 타입·필수 필드·고의 실패와 실제 수신 진입점 검증을 필요한 확인으로 남겼다. 검토 대상 JSON 코드나 helper, 실제 5.1 인계 시험은 실행하지 않았으며 문서 답변만 작성했다.
- **I5:** 제공된 같은 시도 os32를 runtime read/execute 검증의 공유 위반 분류로 다루고 잠금 대상·소유자·정확한 원인은 미확인으로 남겼다. 과거 continuing setup ACL 경고와 이번 원인을 합치지 않았고, browser 성공을 native 캡처 성공으로 인정하지 않았다. 답변의 BLOCKED/UNRESOLVED는 합성 시나리오의 필요한 native 기능 상태이며 이 암묵 선택 시험 자체의 실패 판정이 아니다. 실제 로그·프로브·helper·프로세스 조작·복구는 하지 않았다.

### I4의 지시 충돌 — 읽기 성공과 준수 PASS를 분리

원문은 “PowerShell 코드 실행·helper 실행·환경 업그레이드·설치는 하지 마”라고 했다. **그런데 지침을 읽기 위해 실제로 PowerShell Get-Content 명령 1개를 실행했다.** 검토 대상 검증 코드를 실행하지 않은 것과 PowerShell 프로세스/명령을 전혀 실행하지 않은 것은 다르다.

따라서 이 문구를 문자 그대로 모든 PowerShell 코드 실행 금지로 적용하면 **엄격한 실행 금지 준수는 불일치(NOT_MET)**다. 읽기 전용이거나 파일 해시가 같다는 이유로 이 충돌을 지우지 않는다. I4의 스킬 자동 읽기는 관측됐지만 요청 준수 전체 PASS로 합치지 않는다. “실행 없이”라는 사전 안내 역시 지침 열람용 명령까지 없었다는 뜻으로 받아들이면 부정확하다.

이번에는 시험 원문·배포 스킬·기존 설정을 고치거나 유리한 요청으로 재시험하지 않는다. 지침 열람과 검토 대상 코드 실행을 어느 범위까지 금지하려는지 구분해야 한다는 보완점으로 남긴다. 원래 금지 문구는 최초 입력 근거에 그대로 보존했다.

### 공개 근거·보존·남은 미검증

[추가 비식별 근거](extended-evidence.json)에 원문 입력, NESTED 별칭의 읽기 명령 요약, 완료 상태와 최초 최종 답변을 보관했다. 원시 trace·프로젝트 ID·대화 ID·개인 절대경로·설정 내용/해시는 공개하지 않는다. 전달은 앞선 사례와 같은 create_thread의 codex_delegation wrapper를 사용했으며 사람이 UI에 직접 입력한 전송 경로와는 구별한다. 입력에 스킬명·경로·기대 표식을 넣지 않았고, 추가 선택 유도·재시도·후속 메시지는 없었다.

이번에도 기존 스킬·지침·설정 11개와 임시 패키지 18개, 총 29개 파일의 전후 SHA-256이 같았다. 임시 18개는 실행 전 준비 manifest와도 같았다. 기존 config.toml의 과거 준비 기준 차이는 이전과 같이 보존했으며 이번 구간에는 변하지 않았다. 설치·업데이트·설정 수정·기기 조작·제품 개발은 없었다. 새 대화 3개는 사용자 확인을 위해 남겼다.

이로써 이번 환경에서는 다섯 스킬의 양성 사례를 각 1회, 산술 음성 대조를 1회 관측했다. 이는 일반 호출률·고정 동명 우선순위·스킬의 인과 효과나 완전한 지시 준수율을 입증하지 않는다. I3~I5에 대한 별도의 인접 음성 사례나 반복 안정성도 시험하지 않았다. 선택기 P0·P1, 실제 기기 조율·5.1 인계 코드·native 복구의 성공은 여전히 미검증이다. 승인된 확장 세 사례를 관측했으므로 추가 실행 없이 종료한다.

## 7. I4-R1 — 권한 문구 명확화 후 재시험 1회

사용자는 지침 문서의 읽기 전용 열람은 허용하고 검토 대상 코드·helper 실행은 금지하도록 I4를 보완한 뒤, 같은 임시 프로젝트의 새 대화에서 **한 번만** 재시험하도록 요청했다. 이 명확화는 과거 판정의 재해석이 아니라 새 입력 버전이다.

### 바꾼 문구와 보존

| 버전 | 끝의 실행 권한 문구 |
| --- | --- |
| 기존 I4 | PowerShell 코드 실행·helper 실행·환경 업그레이드·설치는 하지 마. |
| I4-R1 | 지침 문서의 읽기 전용 열람과 그 열람에 필요한 읽기 전용 셸 명령만 허용해. 검토 대상 PowerShell 코드·검증 스크립트·helper 실행, 파일·설정 변경, 환경 업그레이드·설치는 하지 마. |

앞의 상황·PowerShell 버전·JSON 3건·검증 공백·문서 답변 요청은 그대로 두었다. 스킬명·경로·기대 표식은 추가하지 않았다. [수동 안내 I4](../../docs/desktop-manual-skill-check.md)의 현재 복사용 원문을 I4-R1로 바꾸고 버전 설명을 붙였다. 로컬의 고정 커밋 참고 사본과 기존 시험 파일은 수정하지 않았다.

기존 I4의 원문·최초 답변·읽기 명령·엄격한 실행 금지 NOT_MET 판정은 §6과 [extended-evidence.json](extended-evidence.json)에 그대로 보존한다. [기본 세 사례 근거](evidence.json)도 수정하지 않는다. 이번 결과로 과거 충돌을 지우거나 기존 결과를 PASS로 바꾸지 않는다.

### 실제 한 번의 실행

- `list_projects`에서 준비한 NESTED 경로와 같은 등록 로컬 프로젝트를 다시 확인했다.
- `create_thread`로 새 대화 **1개**, 보완 원문 제출 **1회**만 수행했다. 기존 대화를 계속하거나 fork하지 않았고 추가 재시험·후속 질문은 0회다.
- `read_thread.thread.cwd`와 읽기 명령의 실제 cwd가 모두 NESTED에 일치했다. 프로젝트 이름이나 자기 보고만으로 판정하지 않았다.
- 첫 턴의 실행 명령은 `pwsh.exe -Command Get-Content -LiteralPath NESTED/.agents/skills/verify-powershell-handoff/SKILL.md` 형태의 **지침 읽기 1개**였다. 경로는 공개용 별칭이며 원시 명령이 아니다. exit 0, 출력 truncated=false였고 읽힌 본문과 최종 답변에서 `READ_RECEIPT_NESTED_verify-powershell-handoff`를 확인했다.
- 관측된 첫 턴에는 검토 대상 `@(Get-Content file.json | ConvertFrom-Json)`, 검증 스크립트·helper 실행이나 파일·설정 변경 이벤트가 없었다. 허용된 셸 명령이 실제 실행됐으므로 이를 “셸 실행 0”으로 적지 않는다.

이번 지침 읽기는 보완 문구가 명시적으로 허용한 범위와 일치한다. **PATH_READ_OBSERVED + BODY_OBSERVED**, 관측된 실행 범위는 **OBSERVED_WITHIN_REVISED_ALLOWLIST**로 기록한다. 스킬의 자기 보고나 파일 해시 일치만으로 준수를 판단한 것이 아니라 최초 실행 항목을 함께 대조했다.

### 답변과 해석의 한계

답변은 수신자 5.1의 실제 동작을 검증했다고 하지 않고 인계 준비 완료 판정을 보류했다. Count 3·항목 객체/필수 필드·실패 처리·실제 진입점 확인을 미실행 항목으로 남겼다. PowerShell 7 성공은 제공된 상황의 보고이며 이번 시험에서 재현한 결과가 아니다.

최종 답변의 “코드 실행이나 파일 변경은 하지 않았다”는 문구는 관측상 **검토 대상 코드 실행 없음**이라는 범위로만 설명한다. 지침 열람용 PowerShell 명령은 실제로 있었다. 최종 답변의 개인 절대경로 링크만 NESTED로 치환한 [I4-R1 근거](i4-r1-evidence.json)에 원문 변경·실행 요약·최초 최종 답변을 보관했다.

요청문이 바뀌었으므로 이전과 완전히 동일한 입력의 반복 시험은 아니다. 일반적인 지시 준수율·자동 선택률, 고정 동명 우선순위, 문구 변경의 인과 효과까지 입증하지 않는다. 실제 모델/추론 값은 사용한 메타데이터에 노출되지 않았고 지정/변경하지 않았다. 전달은 기존과 같은 전용 도구의 delegation wrapper이며 직접 UI 입력·선택기 시험이 아니다.

### 보존과 종료

이번 전후에도 기존 개인 스킬·사용자 지침/설정 11개와 임시 패키지 18개, 총 **29개 해시가 동일**했다. 실행 전 임시 패키지는 준비 manifest와도 같았다. 과거 준비 기준과 다른 config.toml은 이미 존재하던 차이이며 이번에는 변경·내용 분석·복원하지 않았다. 기존 설치본·설정·앱 설치·환경 복구·제품 개발은 건드리지 않았다.

사용자 승인 범위의 요청문만 보완하고 1회 재시험했으므로 종료한다. 관측된 한 사례에서는 지침 읽기와 검토 대상 실행을 구분했으며 추가 재시험이나 스킬 본문 수정은 하지 않는다. 기존 I4의 NOT_MET와 이번 R1의 제한된 준수 관측은 별도 결과로 유지한다.
