# Desktop 앱 정체·전용 도구 검토 — 2026-10-16

## 결론

설치·실행 메타데이터상 현재 앱은 **OpenAI.Codex 패키지의 Desktop**이다. 창 제목과 매니페스트 표시명이 ChatGPT이고 실행 파일 제품명이 Codex인 상태가 함께 관측됐다. 창 제목만 보고 Codex가 아닌 별개 앱이라고 판단할 수 없다.

그러나 앱 정체 확인이 UI 자동화 허용이나 스킬 시험 통과를 뜻하지 않는다. 현재 제공된 전용 도구로는 준비한 임시 프로젝트의 선택기 목록·항목 선택·칩·본문/읽기 경로 연결을 시험할 수 없었다. Desktop P0·P1·I1·I2·I0와 선택 확장 I3~I5는 **미실행·미검증**으로 유지한다. 제품 오류나 스킬 선택 실패로 판정한 것이 아니다.

후속 암묵 선택 전용 검토는 아래 §6에 별도로 기록했다. 선택기 시험 도구가 없다는 사실과, 준비한 CWD의 새 대화를 생성할 수 있는지는 다른 조건이다.

## 이번 요청과 실제 수행

사용자는 읽기 전용 앱 식별, 자동화 금지를 우회하지 않는 전용 도구의 시험 가능성 검토, 같은 저장소에 비식별 결과 게시를 요청했다. 기존 설치본·설정 변경은 허용하지 않았다.

이번에는 Windows 패키지/프로세스 메타데이터 조회, 전용 프로젝트 목록 조회, 노출된 도구 계약 검토, 보호 파일·임시 패키지 해시 비교만 수행했다. UI 입력·캡처·프로젝트 등록·새 대화 생성·기존 대화 메시지 전송·설치·업데이트·재시작·환경 복구·제품 개발은 하지 않았다.

## 2. 자동화 제한과 전용 도구의 정확한 범위

현재 설치된 `computer-use` 스킬의 `docs/guidance.md`, “Non-negotiable Windows Automation Safety”에는 ChatGPT desktop app UI와 Windows 앱 안의 Codex CLI/확장 자동화를 금지하는 규칙이 있다. 해당 스킬 번들 식별자는 `computer-use/26.1007.71326`이다.

이번 식별 결과로 그 제한이 없어졌다고 해석하지 않았다. 일반 Windows UI Automation, SendInput, CDP/디버그 포트, 내부 IPC·DB 수정 등 다른 경로로 제한된 UI 동작을 재현하지 않았다. 이 제한은 현재 도구의 적용 경계이지 모든 제품·환경에 대한 영구 규칙이라는 주장이 아니다.

전용 도구는 각 도구가 문서화한 기능으로만 평가했다. 앱 내부에 기능이 존재할 가능성과 현재 호출 가능한 도구가 그 기능을 노출하는지는 별개다.

| 전용 수단 | 이번 실행/검토 | 확인할 수 있는 것과 한계 |
| --- | --- | --- |
| `list_projects` | 읽기 전용 호출 성공 | 현재 계정의 등록 프로젝트 메타데이터. 준비한 임시 폴더는 반환된 로컬 프로젝트 목록에 없었다. 새 대화의 실제 CWD·스킬 카탈로그·선택기 행을 증명하지 않음 |
| `list_threads` / `read_thread` / `wait_threads` | 도구 계약만 검토, 호출하지 않음 | 기존 대화 요약/진행 관측. 선택기·칩 원본, 전체 지침 주입과 파일 읽기 trace가 보장된다는 계약은 없음 |
| `create_thread` | 도구 계약만 검토, 호출하지 않음 | 기존 projectId 또는 별도 projectless 대화 생성 등. 준비한 임의 절대경로를 프로젝트로 등록하는 기능이나 스킬 항목/칩 지정 인자가 없음. 이번에는 사용자 소유 새 대화를 만들지 않음 |
| `send_message_to_thread` | 도구 계약만 검토, 호출하지 않음 | 승인된 대화에 일반 메시지를 보냄. 특정 선택기 항목·칩의 전송 시험이 아니고, 기존 대화 재사용은 암묵 시험을 오염시킬 수 있음 |
| `open_in_codex` / `navigate_to_codex_page` | 도구 계약만 검토, 호출하지 않음 | 파일·탭·기존 대화 표시. 임시 폴더의 프로젝트 등록·primary/CWD 확정이나 선택기 시험 도구가 아님 |
| `capture_screen_context` | 호출하지 않음 | 현재 작업의 활성 음성 채팅에서만 허용. 이번 텍스트 대화에 사용할 수 없음 |
| CUA browser 수단 | 현재 제공 계약만 검토, 호출하지 않음 | 현재 native computer API는 비활성. 브라우저 제어를 Desktop 선택기의 대체 관측으로 쓰지 않음 |
| 스킬 검색/선택 전용 endpoint | 노출된 도구 목록에 없음 | 현재 세션의 한계. 앱 내부에도 그런 기능이 없다는 결론은 아님 |

새 projectless 대화나 다른 기존 프로젝트에서 답변이 나오는지 확인하는 것은 준비한 nested CWD의 동명 스킬 시험과 조건이 다르다. 이를 유효 표본으로 만들려고 기존 프로젝트 폴더·설정을 바꾸거나, 이전 결과를 아는 현재 대화에 I1/I2를 다시 넣지 않았다.

## 4. 보존과 공개 범위

- 10/15 준비 manifest에 있는 임시 패키지 파일 18개는 모두 같은 SHA-256이었다.
- 기존 개인 스킬 패키지 9개 파일과 사용자 지침·설정 2개, 총 11개는 이번 기록 구간의 전후 해시가 모두 같았다.
- 10/15 준비 기준과 비교하면 10개는 같고 사용자 `config.toml` 1개는 달랐다. 그 차이는 이번 첫 비교 때 이미 있었으며 원인은 미확인이다. 설정 내용을 읽어 분석하거나 자동 복원하지 않았다. 따라서 “어제 이후 설정 변경 0”이라고 쓰지 않는다.
- 설치 패키지의 실행 파일과 AppxManifest.xml 두 파일도 이번 전후 해시가 같았다. 전체 앱 패키지·PC 무변화를 증명한 것은 아니다.
- 이 게시에는 비식별 설명만 넣는다. 개인 절대경로·PID·프로젝트 목록·원시 trace·설정 본문·개인 설정 해시·계정·장치 식별정보는 올리지 않는다.
- 기존 skills/ 본문, 템플릿, 실제 설치본과 기존 평가 기록은 바꾸지 않는다. 결과 보고서와 안내 링크만 보완한다.

## 5. 앞선 기록의 보완과 종료

[10/15 관측 한계](../desktop-skill-boundary-20261015/README.md)의 초기화 실패는 그 시도의 역사 기록이다. 10/16 앞선 별도 시도에서는 초기화와 앱 목록 조회가 성공했다. 이번에는 런타임을 다시 초기화하거나 UI 시험을 재시도하지 않고 패키지 정체와 도구 경계를 조사했다. 과거의 초기화 실패를 현재의 유일한 차단 원인으로 계속 쓰지 않는다.

앞선 설명에서 창 표시명만으로 제한을 설명한 부분은 불충분했다. 정확한 설명은 **Codex 패키지임을 확인했지만, 현재 ChatGPT 표시의 Desktop UI 자동화 제한과 전용 시험 기능 부족으로 선택기·암묵 선택이 미검증**이라는 것이다.

추가 설치·환경 복구·반복 실행 없이 종료한다. 이후 사람이 [수동 절차](../../docs/desktop-manual-skill-check.md)를 수행하거나, 해당 폴더의 CWD와 스킬 선택/본문 근거를 직접 노출하는 허용된 전용 인터페이스가 제공되는 경우에만 남은 항목을 별도로 확인한다. 실제 관측 전까지 NOT_RUN을 PASS로 바꾸지 않는다.

## 6. 후속: 전용 도구의 새 대화에서 암묵 선택만 가능한가

같은 날 사용자가 선택기 시험을 제외하고 임시 프로젝트의 새 대화에서 I1·I2·I0만 조건부 실행하도록 명시적으로 요청했다. 이번에는 새 대화 생성 권한 부족이 아니라 **준비한 임시 프로젝트에 연결되는 생성 대상과 실제 CWD를 확보할 수 있는지**를 먼저 확인했다. 새 대화 생성과 UI 자동화는 서로 다른 동작이며, 선택기 endpoint가 없다는 사실만으로 암묵 시험도 불가능하다고 일반화하지 않는다.

### 실제 사전 확인

- `list_projects`를 새로 호출해 성공했다. 반환된 로컬 프로젝트 경로를 정규화해 준비한 `TEMP/repo/nested`와 정확히 비교한 결과 일치 항목은 0개였다. `TEMP`는 공개용 별칭이다. 관련 없는 프로젝트 이름·경로·ID는 게시하지 않는다.
- 읽기 전용 `Test-Path`에서 준비한 nested 폴더의 존재는 확인했다. 디스크에 폴더가 있다는 사실은 Desktop 프로젝트 등록이나 새 대화 CWD의 증명이 아니다.
- 현재 `create_thread`의 project 대상은 `list_projects`가 반환한 projectId와 local 환경을 받는다. 준비한 기존 절대경로를 직접 지정하거나 로컬 프로젝트를 등록하는 인자는 없다.
- projectless 대상의 `directoryName`은 출력 디렉터리 이름이다. 이를 기존 절대경로를 여는 기능이라고 해석하거나, 경로 탈출·별칭으로 임시 repo 연결을 시도하지 않았다.
- 현재 노출된 전용 도구에서 임시 폴더의 로컬 프로젝트 등록/primary 지정 기능은 찾지 못했다. 기존 프로젝트를 바꾸거나 내부 저장소를 수정해 등록하지 않았다. 이는 현재 도구 계약의 한계이지 제품의 등록 기능이 없다는 뜻은 아니다.

[공식 Projects and chats](https://learn.chatgpt.com/docs/projects)는 새 대화의 시작 폴더와 지침·스킬 자동 검색의 기준을 primary 폴더로 설명한다. 따라서 다른 프로젝트나 임의 projectless 대화에서 같은 질문에 답을 얻어도 준비한 nested CWD 시험으로 채점하지 않는다. 확인 2026-10-16.

### 실행 여부와 선택기 시험의 구분

| 사례 | 새 대화 생성 | 최초 요청 제출 | 실제 시험 대화 CWD | 판정 |
| --- | --- | --- | --- | --- |
| I1 오류·복구 명세 | 하지 않음 | 하지 않음 | 미확인 | NOT_RUN / UNVERIFIED |
| I2 후보별 인계 근거 | 하지 않음 | 하지 않음 | 미확인 | NOT_RUN / UNVERIFIED |
| I0 산술 음성 대조 | 하지 않음 | 하지 않음 | 미확인 | NOT_RUN / UNVERIFIED |
| P0·P1 선택기 | 이번 요청의 범위 밖 | 하지 않음 | 해당 없음 | 미검증 유지 |

시험 대화를 생성하지 않았으므로 응답·본문 표식·파일 읽기 이벤트·모델/추론 설정 관측도 없다. I0 답이 알려져 있다는 이유로 음성 대조 PASS를 주지 않으며, 이벤트 부재를 미호출 증거로 쓰지 않는다. CLI·서브에이전트·이 준비 대화의 응답으로 대체하지 않았다. 기존 대화에 CWD를 바꾸라는 메시지도 보내지 않았다.

### 재개 조건과 보존

준비한 nested 폴더와 연결되는 등록 프로젝트가 전용 도구에 나타나고, 새 시험 대화의 실제 CWD를 독립적으로 확인할 수 있을 때만 재개한다. 등록 메타데이터만 있고 실제 대화 CWD가 미확인이면 여전히 미검증이다. CWD 확인용 준비 대화가 필요하다면 그것을 I1·I2·I0에 재사용하거나 fork하지 않고, 각 사례의 최초 입력은 [수동 안내](../../docs/desktop-manual-skill-check.md)의 원문만 사용한다. 기대 스킬명·경로·정답표를 덧붙이지 않는다. 실제 CWD가 확인돼도 읽기/본문 근거가 부족하면 답변의 적절성과 스킬 자동 선택 증거를 따로 기록한다.

이번 사전 검토 구간에서도 기존 스킬·지침·설정 11개 파일의 전후 해시는 모두 같았다. 10/15 준비 기준과는 이전에 기록한 설정 1개 차이가 그대로이며 원인을 추정하거나 복원하지 않았다. 앱 설치·업데이트·재시작·환경 복구·기존 프로젝트 변경·새 대화 생성은 하지 않았다. 선택기 미실행과 이번 CWD 사전 조건 미충족을 구별하고, 기존 본문·템플릿 변경 없이 이 후속 기록과 README 요약만 보완한다.
