# Existing team project rules

- TEAM-POLICY-KEEP: 기존 팀의 규칙과 개인 수정본을 보존한다.
- 목적·범위는 [overview](design/overview.md), 기능 계약은 [contract](design/contract.md)에 유지한다. 같은 역할의 docs 문서를 새로 만들지 않는다.
- 현재 작업은 문서 적용·비교뿐이다. 앱 설치·기기 조작·제품 개발·프로세스 중단·설정 변경은 허용하지 않는다.
- 이미 정한 검토 범위와 관련 없는 스킬·전체 시험은 추가하지 않는다.
- services/readonly 아래의 별도 지침은 해당 폴더 작업 전에 확인한다.

## 기존 프로젝트에 병합한 작업 안내

현재 사용자 요청과 위의 팀 규칙·승인 범위를 기준으로 작업한다. 템플릿 적용이 기존 승인이나 보호 대상을 바꾸지 않는다. `services/readonly/AGENTS.override.md`의 읽기 전용 제한은 해당 하위 범위에 계속 적용하며 상위의 문서 작성 안내로 약화하지 않는다.

### 필요한 자료와 스킬만 선택

- 목적·운영 제약·제외 범위는 기존 [overview](design/overview.md), 기능·오류·인수 계약은 기존 [contract](design/contract.md)의 필요한 부분만 읽는다. 작은 수정 때문에 전체 템플릿을 채우거나 `docs/project-brief.md`, `docs/requirements.md`를 중복 생성하지 않는다.
- 개발 명령은 후속 개발이 승인됐을 때 실제 README·설정·기존 시험에서 확인한다. 템플릿으로 도구나 명령을 추정하지 않는다.
- 사용자 지정 스킬은 요청 범위 안에서 사용한다. 그 외에는 아래 조건으로 선택하며 단계 이름만으로 스킬·리뷰·전체 시험을 추가하지 않는다.

| 스킬 | 읽고 적용할 조건 | 생략할 조건 |
| --- | --- | --- |
| `specify-failure-recovery` | 오류·재시도·시간 만료·보존·초기화·비동기 완료·복구·해제 계약을 새로 정의하거나 변경·검토하거나 구체적 누락이 발견됨 | 해당 동작에 영향 없는 오탈자·스타일·이름 수정, 단순 조회·설명, 확인한 계약의 반복 보고. 보존·권한·비동기·재시도에 영향 없고 발생·해제가 명백한 입력 형식 오류는 발생·해제를 직접 두 문장으로 작성 |
| `review-release-evidence` | 이번 요청에서 소스·산출물·시험·승인이 같은 후보를 가리키는지와 완료·릴리즈·인계 범위를 판단함. 또는 후보/시험 근거 충돌·원본 재현 공백·위험 수용·새 관측 없는 프로젝트 검토 반복 때문에 다음 우선순위나 종료 판단이 필요함 | 일반 기능 구현·단위시험·초기 아이디어 정리·작업 완료 요약. 단일 시험의 시간 예산, 한 PowerShell 스크립트의 호환성, 개별 도구 오류 분류처럼 해당 전문 스킬만으로 답할 수 있는 검토 |

명시적 지정이 없으면 두 조건이 모두 맞을 때만 둘 다 사용한다. 기획 단계라는 이유로 첫 스킬을, 테스트·커밋이 있다는 이유로 둘째 스킬을 자동 호출하지 않는다. 필요한 스킬이 없으면 관련 계약을 직접 검토하고 설치 미확인을 짧게 알린다. 자동 설치하거나 그것만으로 작업을 멈추지 않는다.

다섯 동명 스킬의 선택 경로와 보류 사항은 [호환성 결과](design/compatibility-result.md)에 따른다. 설치본은 덮어쓰지 않는다. 특히 프로젝트 `specify-failure-recovery`의 `LOCAL-RECOVERY-KEEP`를 유지하고 사용자 입력을 자동 초기화하지 않는다. `coordinate-device-validation`의 프로젝트 참조 누락과 `diagnose-computer-use-recovery`의 보조 스크립트 개인 수정은 본문 동일성만으로 해소됐다고 판단하지 않는다. 이 문서의 선택은 실제 호스트의 검색 우선순위를 검증했다는 뜻이 아니다.

### 계약·검토·결과의 경계

- 요구 부재·모호한 계약·구현/통합/시험 누락·승인된 추가 범위를 구분한다. 구현 방법이 명세에 없다는 이유로 사용자 요구 누락으로 판단하지 않는다.
- 미정에는 결정 담당·시점·그 전 진행 범위를 적는다. 재시도 수치·권한·삭제 정책을 임의 확정하지 않는다.
- 오류 계약을 다룰 때 발생→보존→복구→해제와 상태/UI 갱신 사건을 연결한다. 재시작이 별도로 승인된 복구라면 이후 사용 가능 상태를 확인한다. 현재 문서 작업은 재시작을 승인하지 않는다.
- 변경한 범위에 필요한 기존 확인만 수행한다. 새 변경·실패·미해결 의문이 없으면 전체 시험이나 독립 리뷰를 반복하지 않는다. 추가 조사는 바꿀 결정·새 관측·전체 상한을 정하고 방법을 바꿔도 상한을 유지한다. 발견 수정분 확인 후 종료한다.
- 소스 확인·모의 시험·실제 환경 검증·사용자 위험 수용을 구분한다. 제공 불가능한 환경은 증명 범위를 한정하며 현재 결정에 필요할 때만 대체 시험을 제안한다.
- 변경 이유·실제 확인·남은 미정/미검증을 필요한 만큼 전달한다. 문서 적용 완료와 제품 구현·설치·배포 완료를 구분하며 사소한 작업에 별도 체크리스트를 강제하지 않는다.
