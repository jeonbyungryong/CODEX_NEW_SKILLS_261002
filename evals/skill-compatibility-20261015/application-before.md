# 독립 문서 적용 검토 결과

2026-10-15. 현재 요청에 주어진 사실과 이 프로젝트의 `AGENTS.md`를 근거로 검토했다. 기기 시험, PowerShell 검증 코드·명령, native 도구 재현은 실행하지 않았다. 아래의 실행·수정 항목은 후속 제안이며 수행 기록이 아니다.

## A1 — 사용자와 agent가 나누어 수행하는 기기 시험

현재 설계는 제시된 시간 조건을 충족하지 못한다. 측정창은 **주입 시작 → 관측 끝, 최대 5초**이고, 창 안의 순서는 **사람 행동 4초 → 수집 4초**이다. 중첩할 수 없으므로 필요한 시간은 8초, 부족분은 3초다. 준비는 이미 창 밖에서 완료했으므로 준비 이동으로 더 줄일 시간이 없다. 준비를 다시 요청하거나 두 단계를 병렬로 계산할 근거도 없다. 이는 현재 절차의 시간 예산 판정이며 기기 결함이나 실제 timeout 분기를 입증한 결과가 아니다.

| 검토 대안 | 성립 조건과 증명 범위 |
| --- | --- |
| 준비를 창 밖으로 이동 | 이미 완료되어 추가 이득이 없다. 현재 설계의 해결책이 되지 않는다. |
| 주입 시작점을 뒤로 이동 | 사람 행동 이후처럼 실제로 식별 가능한 사건에 주입을 맞출 수 있고, 그 전 단계의 노출을 제외해도 원래 목표 주장을 시험하는지 먼저 확인해야 한다. 행동이 주입 상태에서 이루어져야 한다면 같은 시험이 아니다. 주입 시점을 옮기기만 해서 동일한 목표가 충족됐다고 처리할 수 없다. 지원되는 자동 트리거가 있다고 가정하지 않는다. |
| 허용창 연장 | 장치·운영 조건에서 허용된다면 최소 8초가 필요하다. 정확히 8초는 여유가 없으므로 지연·시각 오차의 허용 여유는 별도 근거로 정한다. 5초가 고정된 인수 기준이면 연장은 기준 변경이며, 기존 5초 충족 증거가 되지 않는다. |
| 단계 시간 단축 | 동일한 행동과 관측을 보존한 채 합계를 5초 이하로 만들 수 있다는 새 근거가 필요하다. 현재 사실에는 그런 근거가 없고, 수집기 개발이나 제품 변경은 이번 검토 범위 밖이다. |

실행 재개 전에 시험 책임자가 목표 주장, 시점 변경 시 제외되는 노출, 허용창 변경 가능성을 결정해야 한다. 결정 시점은 실기 시작 전이며, 그 전에는 문서 검토까지만 진행한다. 시작·끝 사건의 시각 출처와 관측 완료 기준도 정해야 한다. 채팅 메시지를 정밀한 시작 시각으로 사용하지 않는다.

종료 조건은 다음과 같다.

- 지금은 실행하지 않고 현재 설계를 시간 조건 미충족으로 종료한다. 같은 설계의 반복은 부족한 3초를 해결하지 않는다.
- 추후 조건이 성립해 실행한다면 한 후보·한 목표에 대해 사용자 실물 관측과 agent 수집 결과를 각각 기록한다. 창 초과, 시작·끝 시각 불명, 필요한 분기 관측 누락은 판정 불가이며 PASS로 합치지 않는다.
- 필요한 판별 결과를 얻으면 반복을 끝낸다. 동일한 판정 불가만 반복되면 새 관측 방법이나 변경된 조건이 마련될 때까지 중단한다. 재개 시 횟수·시간 상한을 먼저 정한다.
- 기기 복귀가 필요하다면 이미 승인된 절차만 따른다. 이번 입력에는 그 절차와 현재 복귀 상태가 없어 성공을 주장할 수 없다.

**판정:** 계획 검토 완료. 현재 설계 실행 불가. 실기 결과·복귀 상태는 미검증.

## A2 — Windows PowerShell 5.1 검증 인계

현재 인계는 준비완료가 아니다. 작성자의 PS7 성공은 작성자 환경에서의 제한된 실행 근거일 뿐, 수신자의 Windows PowerShell 5.1에서 JSON 루트 배열 3건을 각각 검증했다는 증거가 없다.

`@(Get-Content file.json | ConvertFrom-Json)`의 바깥 `@()`만으로 3개 레코드가 보장되지는 않는다. Windows PowerShell 5.1에서는 파싱된 JSON 배열이 파이프라인 객체 하나로 나와 바깥 배열의 Count가 1일 수 있다. 이때 `foreach`가 끝났다는 사실만으로 3건 검증을 입증할 수 없다. Count와 레코드별 타입·필드 확인이 없으므로 실제 반복 대상과 검증 내용이 누락돼 있다. 현재 실행 없이 특정 실패 출력을 단정하지는 않는다.

최소 보완은 다음과 같다. 모두 권고이며 파일 수정이나 실행은 하지 않았다.

1. 수신 엔진을 Windows PowerShell 5.1로 고정하고, 정확한 진입점·호출 인수·작업 디렉터리·입력 파일과 스키마를 인계한다. JSON 디코딩과 스크립트 인코딩을 각각 명시한다. 한글 소스가 있으면 PS5.1에 맞는 UTF-8 BOM 등을 확인해야 하며, 로그 인코딩과 혼동하지 않는다.
2. 파일 전체를 명시적 UTF-8로 읽고 파싱 오류를 실패로 처리한다. 파싱과 컬렉션 구성을 분리하고, **루트 배열·정확히 3건·각 레코드의 타입·필수 필드·허용 값**을 검증한다. 기대 필드 이름은 제공되지 않았으므로 스키마 담당자가 실제 계약으로 결정해야 한다.
3. 3건이 모두 non-null 레코드라는 계약이 확인되면 파싱 결과를 변수에 받은 뒤 컬렉션을 구성하는 방식을 사용할 수 있다. 그 계약은 현재 확인되지 않았다. null·빈 배열의 원형 보존이 필요하면 원래 루트 배열을 확인하고 객체 속성으로 감싸 파싱하는 방식 등으로 원소 수를 보존한 다음 스키마에 따라 null을 명시적으로 거부한다. null 삭제, 임의 평탄화, 기대 Count 완화로 통과시키지 않는다.
4. 수신자의 PS5.1에서 실제 진입점과 대표 3건 입력을 검증하고, 의도적으로 잘못된 입력이 실패하는지 확인할 계획을 인계한다. 빈 배열·1건·여러 건·잘못된 JSON·null 원소는 계약에 맞게 기대 결과를 적는다. 계약이 정확히 3건이면 0건과 1건은 정상 통과 사례가 아니다. 필수 필드 누락·타입 오류도 거부되는지 확인해야 한다.

준비완료를 바꿀 최소 관측은 **같은 인계본을 수신자 PS5.1의 실제 호출 방식으로 실행하여 Count 3과 세 레코드의 스키마 검증을 확인하고, 의도된 실패 입력이 성공으로 보고되지 않는 기록**이다. 실행 담당자는 수신 환경 담당자이며, 인계본 사용 승인 전에 확인해야 한다. 코드·명령 실행 금지인 현재 단계에서는 이 차단 검증을 명시한 검토 결과만 전달한다. 구문·해시 확인이나 다른 래퍼의 성공도 이 런타임 관측을 대체하지 못한다.

native helper 호출이 이 인계에 있다는 정보는 없다. 따라서 인수·종료코드 검증이나 helper 개발을 현재 필수 작업으로 확대하지 않는다. 실제 인계에 native 호출이 포함될 때 그 경계를 별도로 검토한다.

**판정:** 인계 누락 검토 완료, NOT READY. PS5.1의 컬렉션 모양·레코드 검증·실패 전파·인코딩은 미검증. PS7 성공은 제공 사실이며 이번 검토에서 재현하지 않았다.

## A3 — 현재 시도의 native read/execute validation 실패

현재 원인 경계는 **동일 시도의 native runtime read/execute validation에서 발생한 os32 공유 위반**이다. ACL 검증 작업에서 실패했다는 것과 ACL 권한이 잘못됐다는 것은 다른 주장이다. 현재 근거로는 파일 공유 충돌 경계까지 말할 수 있고, 정확한 잠금 소유자·발생 원인·해결 방법은 확정할 수 없다.

generic helper wrapper 추가는 내부 실패를 설명하는 새 관측이 아니다. 다른 시도의 `continuing setup` ACL warning은 현재 os32의 원인 근거로 사용할 수 없으며 비치명적 경고일 수도 있다. 브라우저 성공은 브라우저 표면의 근거다. 요청에 필요한 native 캡처의 가용성이나 복구를 입증하지 못한다. 아직 캡처 단계에 도달했다는 근거도 없어 이를 FrameArrived 캡처 오류로 바꿔 진단하지 않는다.

미확인 사항은 현재 앱·runtime 버전과 도구, 실제 실패 파일·작업, 동일 세션의 정확한 오류 시각, 의도한/실제 sandbox mode, 잠금 소유자다. 프로세스 목록에서 runtime이 보이더라도 해당 파일 핸들의 소유 증거가 되지는 않는다. os5 접근 거부나 1385 로그온 정책 실패도 현재 os32와 혼합하지 않는다.

다음 관측은 **기존 자료를 한 차례 묶어 읽는 것**으로 한정한다. 새 native 재현이나 실행 프로브는 이 과제의 금지 범위이므로 수행하지 않는다.

- 동일 실패의 시각·세션과 연결되는 `sandbox.log`, 해당 날짜의 sandbox 로그, `setup_error.json`에서 read/execute 작업·파일·os32 원문을 확인한다. 파일명이 버전에 따라 바뀔 수 있으므로 존재와 해당 시도를 먼저 맞춘다. 다른 시도 로그나 wrapper 메시지만 있다면 그 한계를 그대로 기록한다.
- 기존의 읽기 가능한 설치·도구 메타데이터와 최소 설정 정보로 버전, native 도구 표면, 의도한/실제 sandbox mode를 확인한다. 전체 설정·인증정보·원시 프로세스 명령행·사용자 경로를 보고서에 복사하지 않는다.
- 이미 허용된 읽기 전용 핸들 근거가 있을 때만 실패 파일과 소유자를 연결한다. 그런 근거가 없으면 잠금 소유자는 UNCONFIRMED로 남긴다. 새 잠금 도구 다운로드·설치·실행으로 확대하지 않는다.

이 관측이 바꿀 결정은 “동일 시도의 underlying os32가 확인됐는가, 다음 조치를 특정 소유자·설정 경계로 좁힐 근거가 있는가”이다. 한 번의 기존 근거 검토 뒤 새 관측이 없으면 같은 로그를 반복해서 원인 확정으로 승격하지 않는다. 이 문서 과제에서는 실제 로그 읽기도 수행하지 않았으므로 위 항목은 후속 읽기 계획이다.

설치·설정 변경·재시작·프로세스 조작은 승인 범위 밖이므로 실행하지 않는다. sandbox 비활성화나 ACL 변경도 해결책으로 적용할 수 없다. 브라우저로는 요청된 native 캡처를 충족할 수 없어 대체 완료로 처리하지 않는다.

**판정:** 진단 검토 완료. 요청된 native 캡처는 BLOCKED/UNRESOLVED, 원인 소유자는 UNCONFIRMED. 후속 읽기로 충분한 새 근거를 얻지 못하거나 다음 단계가 환경 변경을 요구하면 현재 경계에서 중단하고 필요한 확대 범위만 별도로 제시한다. 복구 성공·설정 복원은 수행하거나 검증한 사실이 없다. 향후 허용된 복구가 이루어져도 의도한 mode에서 실제 요청된 캡처를 입증해야 VERIFIED가 된다.

## 실제 사용 지침과 산출물 범위

스킬 경로는 프로젝트 기준 상대 경로다. 개인 PC 절대 경로는 기록하지 않는다.

| 과제 | 실제 읽은 스킬·참조 | 선택 이유 |
| --- | --- | --- |
| 공통 | 프로젝트 `AGENTS.md`; `../../skill-publish/skills/review-release-evidence/SKILL.md` | 검토 범위를 지키고 문서 판단·제공 근거·실행 증거를 구분한다. A1 종료, A2 인계 준비, A3 중단 판단에 적용했다. |
| A1 | `../../skill-publish/skills/coordinate-device-validation/SKILL.md`; `references/timing-budget.md` | 사람·agent의 순차 행동을 동일한 측정창에 합산하고 시간 대안별로 전제와 시험 범위를 구분한다. |
| A2 | `../../skill-publish/skills/verify-powershell-handoff/SKILL.md` | 수신 엔진 차이, JSON 배열의 컬렉션 모양, 필드 검증, 실행 없는 준비완료 판정의 한계를 다룬다. 별도 참조는 읽지 않았다. |

참조 파일의 `references/…`는 각 행의 스킬 디렉터리를 기준으로 한다. `specify-failure-recovery`는 읽지 않았다. A1은 주어진 시간창의 실행 가능성, A2는 입력 검증 인계, A3은 기존 오류의 원인 경계만 검토하며 제품의 보존·재시도·초기화·복구·해제 계약을 새로 정의하거나 변경하지 않기 때문이다. native UI 작업을 하지 않아 설치된 Computer Use 실행 지침과 runtime 참조를 추가로 읽지 않았고, triage 실행을 하지 않아 입력 계약 참조도 읽지 않았다.

산출물은 이 `docs/results.md` 한 파일이다. 실제 수행한 확인은 지정 프로젝트 지침, 선택한 네 스킬과 위 참조의 읽기, 시간 예산 산술, 작성 문서의 검토뿐이다. 앱·제품/시험 코드·기기·설정·프로세스·패키지·공유 Git은 변경하지 않았다. 다른 평가폴더·점수표·이전 보고서·다른 agent 답은 읽지 않았다. 실기·PS5.1·native 재현 및 로그 검증은 모두 미수행으로 남는다.
