# 다섯 스킬의 미설치와 기존 프로젝트 호환성 시험

기준일: 2026-10-15. 시작 커밋: `7af28b4d75e8354a54659319ec11928ee1b71fe8`.

후속 [실제 Codex CLI 검색·선택 시험](../codex-skill-discovery-20261015/README.md)에서 동명본 노출과 명시 호출의 실제 읽기 경로를 추가 확인했다. 아래는 당시 문서 시험의 범위로 보존하며 Desktop UI·암묵 선택 등까지 검증 완료로 바꾸지 않는다.

대상은 저장소의 `specify-failure-recovery`, `review-release-evidence`, `coordinate-device-validation`, `verify-powershell-handoff`, `diagnose-computer-use-recovery` 다섯 스킬이다. 처음 세 독립 서브에이전트가 미설치 과제, 기존 지침·동일 이름 충돌, 나머지 세 스킬의 정상 문서 적용을 나눠 수행했다. 발견 수정분은 새 컨텍스트의 두 서브에이전트가 전문 검토와 후보별 인계 검토로 나눠 재시험했다. 앱 설치·제품 개발·실제 기기 조작·프로세스/설정 변경은 금지했으며 하위 에이전트의 추가 위임도 허용하지 않았다.

## 재현한 상태와 한계

- 미설치 프로젝트에는 스킬 폴더가 없고, 에이전트의 허용 자료를 해당 프로젝트로 제한했다. 실제 사용자 전역 설치본이나 호스트의 카탈로그를 제거하지 않았다. 이 결과는 파일·접근 범위로 재현한 미설치 상황이며, 새 Codex 호스트의 검색·등록 시험이 아니다.
- 기존 프로젝트에는 `AGENTS.md`, `design/overview.md`, `design/contract.md`, 읽기 전용 서비스의 `AGENTS.override.md`와 프로젝트 스킬 다섯 개를 두었다. 별도 개인 스킬 복사본도 같은 이름 다섯 개를 갖는다. 실제 사용자 설치본은 변경하지 않는다.
- 정상 적용 프로젝트는 저장소의 관련 스킬과 필요한 참조만 읽을 수 있다. 시험은 계획·명세·진단 문서 작성이며 실제 시스템 동작의 PASS가 아니다.
- 에이전트에 사전 기대 판정이나 다른 사례의 결과는 주지 않았다. 파일 산출물·보존 해시·스킬 선택 보고로 판정하며 전체 도구 호출 trace나 자동 선택률은 측정하지 않는다.

## 기존 설치 시험 자료의 차이

아래 차이는 실행 전에 만든 가상 시험 자료다. 개인 복사본은 시작 커밋의 원본 전체이며 프로젝트 복사본만 다음처럼 구성했다.

| 프로젝트의 동일 이름 | 만든 차이 |
| --- | --- |
| `review-release-evidence` | 원본 전체와 동일 |
| `verify-powershell-handoff` | 원본 전체와 동일 |
| `specify-failure-recovery` | `SKILL.md`에 입력 자동 초기화를 금지하는 `LOCAL-RECOVERY-KEEP` 프로젝트 보완 추가 |
| `coordinate-device-validation` | `SKILL.md`는 동일하지만 필요한 `references/timing-budget.md`가 없음 |
| `diagnose-computer-use-recovery` | `SKILL.md`는 동일하지만 `scripts/triage.py`에 실행하지 않는 시험용 개인 주석 추가 |

기존 팀 지침은 `TEAM-POLICY-KEEP`를 보존하고 기획·명세를 `design/`에 유지하며 앱 설치·기기 조작·제품 개발·프로세스 중단·설정 변경을 금지한다. 하위 `services/readonly` 지침은 해당 폴더의 읽기만 허용한다. 보호할 설치 파일·기존 문서·하위 지침 총 20개 파일의 시험 전 해시를 기록했다.

## 입력과 산출물

M1은 메모 저장 응답 유실·인증 만료에 대한 입력 보존과 해제를 묻고 자동 재시도·만료 후 편집 정책은 미정으로 줬다. M2는 A 실사용 PASS, B 모의 PASS, B 실사용 미검증 위험을 사용자가 수용한 제한 시범 운영 인계 승인을 줬다. M3~M5는 A1~A3의 시간 예산·PS5.1·native 사실을 사용했다. C 묶음도 명시 경로를 고른 뒤 같은 다섯 질문에 짧게 답하도록 했다. 설치·복구 실행이나 제품 구현 요청으로 바꾸지 않았다.

## 관측된 문제와 최소 보완

보완 전 전문 검토 에이전트는 공통으로 `review-release-evidence`를 읽고 **“A1 종료, A2 인계 준비, A3 중단 판단에 적용했다”**고 기록했다. 세 과제에는 후보별 소스·산출물·승인 관계나 프로젝트 릴리즈 범위의 추가 판단이 없었다. 각 전문 스킬만으로 답할 수 있어 이 공통 로딩을 과잉으로 판정했다. 답변 자체의 시간·컬렉션·실패 경계 판단은 별개로 수락했다.

템플릿의 `review-release-evidence` 조건 한 행을 후보별 근거와 프로젝트 수용·종료 범위로 좁혔다. 단일 시간 예산·스크립트 호환성·도구 오류 분류는 전문 스킬만 선택하도록 생략 조건도 적었다. 사용 안내에는 같은 경계와 기존 지침·패키지 전체 비교 방법만 보완했다. 다섯 `SKILL.md`, 참조·helper, 기획·명세 템플릿, 실제 개인 설치본이나 전역 설정은 변경하지 않는다.

기존 패키지 비교와 지침 보존에는 관측된 덮어쓰기·문서 중복 생성이 없었다. 이를 실패 사례로 꾸미거나 모든 패키지에 방어 문구를 추가하지 않았다.

| `verify-powershell-handoff` | M4: 수신 5.1의 배열 모양·건수·필드 실행 근거 없음을 기록 | C4: 완전 중복인 프로젝트본 재사용, PS7 성공을 5.1 READY로 전환하지 않음 | A2: 전문 스킬만 사용, 수신 엔진·스키마·실패 경로 미검증 유지 |
| `diagnose-computer-use-recovery` | M5: 현재 native 경계·과거 경고·browser 분리, 원인 미확인 유지 | C5: 개인 helper 수정 보존, 프로젝트 내용으로 수동 분류, helper 미실행 | A3: 전문 스킬+복구 참조만 사용, 잠금 소유자 미확인과 필수 native 캡처 미해결 유지 |

전문 재시험은 `review-release-evidence`와 `specify-failure-recovery`를 읽지 않았고 그 이유를 기록했다. 필요한 후보별 인계 대조는 `review-release-evidence`를 읽고 다른 스킬을 생략했다. 이는 이번 두 응답의 선택 보고이며 일반적인 자동 선택률이나 인과 효과를 뜻하지 않는다.

검토자가 답변 본문에서 발견한 표현 두 곳도 수정했다. A2 재시험의 “알려진 비-null 배열”은 입력에 없는 확정이어서 **non-null 계약이 확인된 경우에만** 예시를 적용하도록 정정했다. 이 조건은 기존 스킬에 이미 있어 본문은 바꾸지 않았다. C2의 “인계 완료”에는 승인/문서 판단만 완료됐고 전달·배포 실행은 미확인이라는 문장을 덧붙였다. 이 정정은 같은 에이전트의 해당 문단 재확인이며 추가 독립 재시험 성공으로 세지 않는다.

부모 검토자는 실제 산출물과 선택 보고를 읽고, 시험 전 기준과 대조했다. 보호 파일 20개의 최종 SHA-256도 직접 다시 비교해 변경 0개를 확인했다. 기존 `design` 문서·하위 읽기 전용 지침·프로젝트 및 개인 스킬 시험본을 보존했고 중복 `docs` 문서는 생성하지 않았다. 결과 문서와 병합할 루트 지침만 작성했다. 공개 자료에는 사용자 PC 절대 경로·실제 로그·인증정보를 넣지 않았다.

## 다음 프로젝트에 적용할 규칙과 종료 범위

1. 필요한 계약이나 후보 판정이 있을 때만 스킬을 읽는다. 전문 검토의 단순 “완료·인계·중단” 표현을 전체 릴리즈 검토의 호출 조건으로 쓰지 않는다.
2. 스킬이 없으면 가능한 문서 검토를 직접 하고 한계를 알린다. 자동 설치나 불필요한 작업 중단으로 바꾸지 않는다.
3. 기존 지침·문서 경로·하위 제한을 먼저 보존한다. 같은 이름의 스킬은 본문뿐 아니라 필요한 파일 집합까지 비교하고 사용 경로를 명시한다. 수정본 덮어쓰기·중복 설치·자동 삭제는 하지 않는다.
4. 주어진 건수만으로 null 정책·스키마를 확정하지 않는다. 문서 검토 완료·위험 수용 승인·전달 실행·실제 시험 PASS를 별도로 보고한다.

현재 요청의 문서 시험과 발견 수정분 확인으로 종료한다. 호스트의 실제 미설치·자동 검색·동명 우선순위, 캐시/재시작 동작, 신규 PC 설치는 **미검증**이다. 실물 시험, PowerShell 5.1 실행, native 복구와 장기 신뢰도도 이번 범위 밖이다. 필요한 실제 목표와 권한이 생길 때만 해당 검증을 별도 수행하며, 이 미검증을 해소하려고 앱 설치나 제품 개발을 추가하지 않는다.
