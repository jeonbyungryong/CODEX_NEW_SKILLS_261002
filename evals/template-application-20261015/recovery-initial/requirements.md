# 사내 웹 메모 편집·저장 및 오류 복구 명세

상태: 검토용 초안 · 기준일: 2026-10-15 · 기준 기획: [초기 기획](project-brief.md) · 결정 담당: 역할 지정부터 미정

범위는 기능과 복구 계약 작성이다. 제품·시험 구현, 설치, 실제 통신·실행 검증은 수행하지 않는다. 인수 조건은 향후 검증 계획이며 통과 기록이 아니다.

## 저장의 의미와 상태

- 현재 입력: 마지막으로 편집한 내용. 실패나 응답 처리로 자동 삭제·이전 내용 대체를 하지 않는다.
- 저장 대상본: 저장 시작 시 고정한 편집본. 시작 후 입력은 별도 최신 편집본으로 유지한다.
- 마지막 확인 정상본: 해당 계정·메모의 서버 내구 저장이 확인된 편집본과 서버 버전. 접수·전송 완료만으로 갱신하지 않는다. 신규 메모에는 없을 수 있다.
- 저장 완료: 내구 저장 확인 결과가 같은 계정·메모·요청·편집본에 대응하고 현재 입력과 일치할 때만 표시한다. 서버에 저장됐어도 응답 유실 시 클라이언트는 완료를 아직 확인하지 못한다.

| 화면 상태 | 의미·갱신 사건 |
| --- | --- |
| 미저장 | 입력 변경 시 진입. 이전 요청 성공 뒤에도 이후 편집이 있으면 유지 |
| 저장 중 | 유효한 인증으로 저장 대상본을 전송할 때 진입. 접수는 완료가 아님 |
| 저장 여부 확인 필요 | 전송 후 단절·응답 유실·응답 확인 기한 경과로 결과를 모를 때 진입. 기한은 D-01 |
| 저장 실패 | 서버가 해당 건의 미저장을 확정한 경우. 입력 유지·복구 행동 제공 |
| 재인증 필요 | 만료 감지 시 전송 중단. 진행 중 저장의 불확정 여부는 별도 유지 |
| 저장 완료 | 유효한 응답 또는 같은 건의 결과 조회로 내구 저장 확인 후 최신 입력과 같을 때 진입 |

인증 상태와 저장 상태를 함께 표시할 수 있어야 한다. 예: “재인증 필요 · 이전 저장 여부 확인 필요”. 단순 재접속·시간 경과만으로 완료나 오류 해제를 표시하지 않는다.

## 기능 요구

### REQ-001 메모 편집과 서버 저장

- 우선순위: 입력 보존과 실제 저장 여부의 정확한 표시를 최우선으로 한다.
- 전제: 메모 소유 계정으로 인증하고 저장 권한이 있다. 계정·메모·요청 식별자, 대상 편집본 식별자·기준 서버 버전을 요청과 결과에 대응시킨다. 전송 방식과 저장 기술은 지정하지 않는다.
- 정상 흐름: 편집 → 미저장 표시 → 저장 대상본 고정 → 서버 권한·버전 확인과 내구 저장 → 결과 확인 → 해당 정상본 갱신 → 최신 입력과 같으면 완료, 다르면 미저장 표시.
- 보존: 현재 입력·진행 중 대상본·정상본·귀속 정보를 구분한다. 실패·응답 유실·재인증 요청만으로 초기화하지 않는다. 종료·로그아웃 시 보존·삭제는 D-02이며 자동 삭제 승인으로 해석하지 않는다.
- 첫 저장: 정상본이 없어도 입력 유지. 실패 시 빈 정상본으로 되돌리지 않는다. 첫 내구 저장 확인 후 정상본을 만든다.
- 인수 조건: 저장 중 추가 편집 → 이전 성공 응답 도착 → 추가 입력 유지, 이전 대상본만 정상본 갱신, 최신 입력은 미저장 표시.

### REQ-002 동일 저장 건 확인과 중복 방지

- 응답 유실 후 같은 계정·메모·요청 식별자로 결과를 확인한다. 같은 건 재전송이 새 메모나 중복 변경을 만들지 않아야 한다.
- 재시도는 동일 대상본·동일 요청 식별자를 사용한다. 새 입력을 이전 요청에 끼워 보내지 않는다. 새 저장은 별도 요청으로 식별한다.
- 미확인 요청과 후속 저장이 서로 덮어쓰지 않도록 서버 버전·요청 순서를 검증한다. 충돌·불명은 입력을 보존하며 표시하고 자동 덮어쓰기로 해결하지 않는다.
- 인수 조건: 서버 내구 저장 직후 응답 유실 → 조회 또는 같은 건 재시도 → 한 건의 결과 확인, 중복 생성 없음, 최신 입력 유지.

### REQ-003 인증과 계정 경계

- 초안·대기 요청·미확인 결과는 원래 계정·메모에 귀속하며 현재 로그인 계정으로 자동 변경하지 않는다.
- 만료 감지 시 신규 전송·자동 재시도 중단. 서버는 실제 쓰기 시점에도 인증·권한을 검증한다. 만료 감지만으로 이미 처리된 요청을 실패라 단정하지 않는다.
- 동일 계정 재인증 후 권한·미확인 결과를 확인하고 저장 가능 상태를 갱신한다. 결과 확인 전 완료 표시하지 않는다.
- 다른 계정 로그인 시 이전 계정 요청을 보내거나 초안을 새 계정 편집창에 노출하지 않는다. 복원은 원래 계정 인증·접근 확인 후 수행한다.
- 만료 후 신규 편집 허용 여부는 D-03 미정. 어느 선택에서도 기존 입력 유지·다른 계정 자동 전송 금지를 적용한다.
- 인수 조건: A 저장 중 만료 → B 로그인 → A 요청 전송·초안 노출 없음 → A 재인증 후 A 결과를 확인하고 복구 가능.

## 브라우저 종료와 로컬 복구 경계

실행 중 저장 실패로 입력을 버리는 것은 금지한다. 종료·강제 종료·재실행 뒤 어떤 입력을 얼마나 보존할지, 로컬 접근 보호·암호화·로그아웃·삭제 기준은 D-02 미정이다. 메모리나 특정 저장 기술만으로 종료 후 보존을 보장하지 않는다.

정책 확정 시 보존 대상, 기록 완료 관측, 재실행 후 원래 계정 확인·복원, 만료·삭제 갱신 사건, 공간 부족·손상 시 입력 보호와 안내를 연결한다. 로컬 자료가 없거나 손상됐다는 이유로 서버 정상본·다른 복구 가능본을 자동 삭제하지 않는다. 결정 전 종료 후 무손실 복구를 제품 약속으로 내걸 수 없다.
