현재 설계로는 **15초 표시 timeout을 입증하는 실행 순서를 확정할 수 없습니다.** 스킬의 시간 예산 기준에 따라 실행은 보류해야 합니다.

주입 시작을 `t=0`으로 잡으면 순차 실행의 최악 시간은 다음과 같습니다.

| 단계 | 소요 시간 | 누적 시간 |
|---|---:|---:|
| 시작 신호 확인·적용 누름 | 4초 | 4초 |
| 로그 수집 시작·확인 | 2초 | 6초 |
| 유효성 확인 | 10초 | 16초 |
| 실제 표시 대기 | 15초 | 31초 |

고장 주입은 **25초에 종료**되므로, 최악 조건에서는 표시 대기 중 **9초만** 고장이 유지됩니다. 필요한 시간보다 **6초 부족**하며, 순서만 바꿔도 합계는 같습니다.

가능한 재설계는 다음 세 가지지만, 모두 현재 조건에서는 확정할 수 없는 조건부 대안입니다.

- **준비 6초를 주입 전에 완료:** 실제 적용 조작까지 밖으로 옮겨도 같은 시험인지 확인해야 합니다. 가능해도 `10+15=25초`로 여유가 없습니다.
- **유효성 확인 뒤 주입 시작:** 해당 사건을 관측하고 시작을 맞출 수 있어야 합니다. 표시 단계 장애 시험으로 범위가 달라지며, 기존 전체 경로 시험과 동일하지 않습니다.
- **주입창 연장:** 최소 31초에 지연·측정 오차 여유가 추가로 필요합니다. 허용 여부와 여유값은 주어지지 않았습니다.

또한 판정에는 **실제 표시 대기 시작, timeout 발생, 주입 종료 시각과 표시 timeout 분기를 구별하는 근거**가 필요합니다. 채팅 시작 신호나 경과시간만으로는 입증할 수 없습니다.

따라서 장치·코드 변경 없이 현재 조건을 유지한다면 결론은 **시험 설계 불충족—입증 불가**입니다.
