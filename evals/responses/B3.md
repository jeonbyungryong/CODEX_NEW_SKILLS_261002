**현재 조건으로는 15초 표시 timeout을 입증하는 실행 절차를 확정할 수 없습니다.** `coordinate-device-validation`의 시간 예산 기준에 따라 실행은 보류해야 합니다.

주입 시작을 `t=0`으로 두고 순차 실행하면, 최악 시간표는 다음과 같습니다.

| 단계 | 소요 시간 | 누적 시간 |
|---|---:|---:|
| 로그 수집 시작·확인 | 2초 | 2초 |
| 사용자 시작 신호 확인·적용 | 최대 4초 | 6초 |
| 유효성 확인 | 최악 10초 | 16초 |
| 실제 표시 대기 | 최대 15초 | 31초 |

**총 31초로 주입창 25초보다 6초 부족합니다.** 표시 대기가 16초에 시작하면 주입 종료까지는 9초뿐입니다. 순서만 바꿔도 모두 순차 실행인 이상 총시간은 같습니다. 주입 종료 후까지 기다리는 것으로는 고장이 유지된 상태의 15초 timeout을 보장할 수 없습니다.

검토 가능한 변경안은 모두 조건부입니다.

- **준비를 주입 전에 완료:** 6초를 전부 제외해도 `10+15=25초`로 여유가 없습니다. 특히 ‘적용 누르기’까지 앞당겨도 같은 시험인지 확인해야 하며, 창 안에 남는 조작 시간은 다시 합산해야 합니다.
- **유효성 확인 후 주입 시작:** 표시 대기 시작과 주입을 맞출 수 있고 그 사건을 관측할 수 있어야 합니다. 표시 단계 장애만 검증하며, 검증 단계를 포함한 전체 경로 장애의 증명은 아닙니다.
- **주입창 연장:** 현재 순서를 유지하려면 최소 31초에 별도의 지연·측정 오차 여유가 필요합니다. 연장 허용 여부와 여유값은 주어지지 않았습니다.

조건이 해결된 뒤에는 **주입 시작·종료, 표시 대기 시작, 표시 timeout 발생**의 시각과 timeout 분기를 구별하는 근거를 확보해야 합니다. 채팅 신호나 단순히 15초가 흘렀다는 사실만으로는 충분하지 않습니다.

따라서 현재 결론은 **절차 확정 불가·시험 미실행**입니다. 장치·코드를 변경하지 않는 조건에서는 위 대안의 가능 여부가 확인되기 전까지 입증 가능한 실행 순서를 제시할 수 없습니다.
