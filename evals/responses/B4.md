현재 조건으로는 **15초 표시 timeout을 입증할 실행 순서를 확정할 수 없습니다.** 요청하신 `coordinate-device-validation` 스킬에 따라 순차 시간 예산을 계산한 결과입니다.

주입 시작을 `t=0`으로 두면:

| 순서 | 단계 | 최악 기준 구간 |
|---|---|---|
| 1 | 로그 수집 시작·확인 | 0~2초 |
| 2 | 사용자가 시작 신호를 읽고 적용 | 2~6초 |
| 3 | 유효성 확인 | 6~16초 |
| 4 | 실제 표시 대기 | 16~31초 |

**총 31초로, 25초 주입창보다 6초 부족합니다.** 표시 대기 시작 후 9초에 주입이 끝나므로, 고장이 유지된 상태의 15초 timeout을 보장하지 못합니다. 순서만 바꿔도 순차 합계는 같습니다.

가능한 대안은 모두 조건부입니다.

- **준비 6초를 주입 전으로 이동:** 실제 적용 조작까지 창 밖으로 옮겨도 시험 조건이 유지되는지 확인해야 합니다. 전부 제외해도 10+15=25초로 여유가 없습니다. 현재 설계 그대로는 적용할 수 없습니다.
- **유효성 확인 종료 후 주입 시작:** 그 사건을 관측하고 주입을 맞출 수 있어야 합니다. 표시 단계만 시험하며, 검증을 포함한 전체 경로의 장애 시험과는 범위가 달라집니다.
- **주입창 연장:** 최소 31초와 별도의 지연·측정 오차 여유가 필요합니다. 연장 가능 여부와 여유값은 주어지지 않았습니다.

장치·코드 변경이 불가능하고 위 대안의 지원 여부도 확인되지 않았으므로 **현재 시험은 실행 보류**가 맞습니다. 이후 조건이 확보되면 표시 대기 시작과 timeout 발생 시각, 해당 실패 분기를 구별할 근거가 필요합니다. 단순히 15초가 지났다는 사실만으로는 timeout 입증이 되지 않습니다.
