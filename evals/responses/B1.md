**현재 조건으로는 15초 표시 timeout을 입증하는 실행 절차를 확정할 수 없습니다.** `coordinate-device-validation`의 시간 예산 기준에 따라 실행 보류가 맞습니다.

주입 시작 후 순차 실행에 필요한 최악 시간은 다음과 같습니다.

`로그 시작·확인 2초 + 사용자 반응·적용 4초 + 유효성 확인 10초 + 표시 대기 15초 = 31초`

주입창은 25초이므로 **6초 부족**합니다. 표시 대기 전에 최대 16초가 소요되어, 고장이 유지되는 표시 대기 시간은 9초뿐입니다. 순서만 바꿔도 합계는 같습니다.

가능한 대안은 모두 조건부입니다.

| 대안 | 필요한 확인 및 한계 |
|---|---|
| 사용자 준비·로그 수집을 주입 전에 완료 | 6초를 전부 옮겨도 25초로 여유가 없습니다. 실제 적용 조작이 남으면 그 시간도 필요합니다. |
| 유효성 확인 종료 후 주입 시작 | 해당 사건을 관측하고 주입을 맞출 수 있어야 합니다. 표시 단계 장애만 시험하며, 전체 적용 경로 장애 시험과는 다릅니다. |
| 주입창 연장 | 최소 31초에 별도의 지연·측정 오차 여유가 필요합니다. 연장 가능 여부는 주어지지 않았습니다. |

입증 시에는 **주입 시작·종료, 실제 표시 대기 시작, timeout 발생**을 관측 가능한 시각으로 기록하고, 다른 실패와 구별되는 로그·상태가 필요합니다. 채팅 시작 신호나 단순히 15초가 지났다는 사실만으로는 입증할 수 없습니다.

장치·코드를 변경할 수 없는 현재 범위에서는 위 대안의 지원 여부가 확인되기 전까지 **절차 확정 보류이며, timeout 입증은 미완료**입니다.
