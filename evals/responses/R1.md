**현재 조건으로는 15초 표시 timeout을 보장해 입증할 실행 순서를 확정할 수 없습니다.** 요청하신 `coordinate-device-validation` 스킬에 따라 시간 예산을 검토한 결과입니다.

주입 시작을 0초로 놓으면, 순차 실행 예시는 다음과 같습니다.

| 단계 | 최악 기준 구간 |
|---|---:|
| 로그 수집 시작·확인 | 0~2초 |
| 사용자 신호 확인·적용 | 2~6초 |
| 유효성 확인 | 6~16초 |
| 실제 표시 대기 | 16~31초 |

총 **2 + 4 + 10 + 15 = 31초**로, 주입창보다 **6초 부족**합니다. 표시 대기 시작 시 주입창은 9초만 남습니다. 순서를 바꿔도 모두 창 안에서 순차 실행하는 한 합계는 같습니다.

가능한 대안은 모두 조건부입니다.

- **준비를 창 밖으로 이동:** 6초를 실제로 모두 제거할 수 있어야 합니다. 그래도 25초로 여유가 없으며, 창 안에 적용 조작이 남으면 다시 합산해야 합니다.
- **유효성 확인 종료 후 주입 시작:** 해당 사건을 관측하고 주입을 맞출 수 있어야 합니다. 검증 단계의 고장 노출이 제외되므로, 표시 단계만 시험하는 조건을 수용해야 합니다.
- **주입창 연장:** 최소 31초에 별도 지연·측정 오차 여유가 필요합니다. 연장 허용 여부는 주어지지 않았습니다.

따라서 **현재는 실행 보류**입니다. 장치·코드를 변경하지 않고 위 대안이 가능한지도 확인되지 않았습니다.

향후 입증에는 주입 시작·종료, **표시 대기 시작부터 timeout 발생까지의 15초**, 다른 실패와 구별되는 관측 근거가 필요합니다. 빠른 개별 실행에서 관측될 가능성까지 부정하는 것은 아니지만, 창을 놓치거나 실패 원인을 구별하지 못한 결과는 **판정 불가**입니다.
