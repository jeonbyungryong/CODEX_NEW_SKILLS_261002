## 현재 상태 요약

2026-10-03 문서 갱신 · v0.2 제한적 채택은 유지합니다. 실기시험 조율과 Windows PowerShell 인계 검증 Skill 2개를 구성했습니다. 가상 응답 비교와 일부 실제 로컬 실행을 검증했으며 실제 기기·브라우저 복구 효과나 전체 프로젝트 효율 향상을 입증한 제품은 아닙니다.

- 범위·수용 기준, 실행 계층 진단, 재개 지원 후보 3개는 이번 기준선에서 추가 Skill 필요성이 확인되지 않아 생성 보류했습니다.
- 같은 입력에서 5.1 배열 수집/Count 결함을 놓친 검토 응답은 Skill 적용 전 5/5, 적용 후 0/5였습니다. PowerShell 5.1·7의 기초 실행 시험은 각각 17개 통과했으나 전체 운영 인계가 검증된 것은 아닙니다.
- 기존 제품 전용 release-gate는 유지합니다. 이 저장소에 복제하거나 전역 교체하지 않습니다.
- 이 저장소는 지침 파일 모음입니다. 브라우저 연결·포트·권한을 고치는 프로그램이나 장치 제어 도구가 아닙니다.
- Computer Use 특화 Skill은 생성 보류입니다. 후속 시험에서 내장 브라우저와 Chrome 공식 확장 경로의 작은 합성 파일 전송을 각각 확인했습니다. Chrome은 사용자 파일 URL 접근 설정 변경 보고 후 업로드 1회·다운로드와 전체 바이트 일치까지 확인했지만, 새 Skill의 추가 효과를 입증한 것은 아닙니다. 화면 번역·권한 차단·시험 서버 강제 종료의 한계는 [후속 검토](docs/computer-use-assessment.md#2026-10-03-파일-전송-후속-검토)에 분리했습니다. Edge 파일 전송·대용량 파일·Windows 기본 파일 대화상자와 Windows UI URL 판별 복구는 미검증입니다.
- 단일 Windows PC에서 두 Skill 설치·3개 파일 일치·명시 경로 지정 적용·후속 사용 가능 목록 등록을 확인했습니다. 적절한 자동 선택, 실제 장치 수락, 사용자 시간·토큰 절감은 미검증입니다. [설치 후 검증 범위](docs/installation-verification.md)를 참고하세요.

## Skill 설치

먼저 [설치·사용 안내](docs/usage.md)를 읽고, 파일 지정 방식으로 시험할 수 있습니다. 전역 설치를 원하면 Codex에 아래처럼 요청하세요.

```text
https://github.com/jeonbyungryong/CODEX_NEW_SKILLS_261002 의
skills/coordinate-device-validation 을 검토한 뒤 설치해줘.
같은 이름의 기존 Skill이 있으면 덮어쓰지 말고 차이를 먼저 알려줘.
```

PowerShell 인계에는 같은 방식으로 `skills/verify-powershell-handoff`를 지정하세요. 둘 다 자동 전역 설치하지 않습니다.

설치 요청 예시일 뿐, 이 저장소를 열거나 다운로드한 것으로 설치가 완료되지는 않습니다. 설치 도구의 결과와 실제 선택 여부를 별도로 확인해야 합니다.

## 기본 사용 흐름

1. 시험 목표, 승인 범위, 현재 기기·화면·연결 상태를 제공합니다.
2. 준비·행동·관측·종료를 짧게 정리하고 시간 예산을 검토합니다.
3. 조건이 맞을 때만 실행합니다. 범위 변경이나 새 권한이 필요한 대안은 조건부로 남깁니다.
4. 사용자 실물 관측과 agent 로그를 구분해 결과·복귀 상태를 기록합니다.

설치되어 사용 가능한 환경에서는 `$coordinate-device-validation`을 요청에 포함할 수 있습니다. 단순 문장 수정·일반 상태 보고·단위시험에는 이 Skill을 사용할 필요가 없습니다.

Windows 스크립트 인계 검토에서는 `$verify-powershell-handoff` 또는 해당 파일을 지정하고, 수신자의 실제 셸·실행 방법·manifest 계약·증거를 제공합니다. 대상 엔진의 배열 구조, 인수 경계, 인코딩과 실패 차단을 확인합니다. Git 게시·브라우저 권한 복구·태블릿 수락 판정을 대신하지 않습니다.

## 자료와 백업

- `skills/`: 실제 지침과 필요한 참조만 포함합니다.
- `docs/`: 설계, 사용법, 검증 범위와 알려진 한계입니다.
- `evals/`: 가상 사례와 비교 응답입니다. 실제 장치 로그가 아닙니다.
- 과거 상태는 Git 커밋과 작업 브랜치로 보존합니다. 기존 저장소 파일을 통째로 지우거나 강제 push하지 않습니다.

## 꼭 지킬 사항

- 프로젝트 승인 기준이 우선입니다. 특정 제품의 리셋 허용 기준을 다른 제품에 그대로 적용하지 마세요.
- 시간 부족·분기 불명·미실시를 PASS로 바꾸지 마세요. 복구 성공은 원인 규명과 별개입니다.
- 실제 조작은 제공된 도구·권한·복구 범위 안에서만 수행합니다. 이 Skill 자체는 권한을 부여하지 않습니다.
- 인증정보, 서명 키, APK, 회사 내부 원본·장치 식별정보를 이 저장소에 넣지 마세요.
- 별도의 라이선스는 아직 지정하지 않았습니다. 공개 저장소라는 이유만으로 특정 오픈소스 라이선스가 적용된다고 간주하지 마세요.
