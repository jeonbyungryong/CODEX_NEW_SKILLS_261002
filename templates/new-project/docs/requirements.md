# 기능과 오류 복구 명세

상태: [초안/합의됨] · 기준 기획: [project-brief.md](project-brief.md) · 결정 담당: [역할 또는 미정]

요구마다 필요한 카드만 복사한다. 작은 입력 검증은 정상 입력·오류 발생·수정 후 해제와 인수 조건만 작성한다. 저장·비동기 처리·인증·배포가 없다면 관련 절을 생략한다. `[입력]`은 프로젝트에서 결정할 값이며 스킬 호출 지시가 아니다.

## 오류와 해제 카드

복구 계약이 필요한 기능에만 작성한다. 내부 정상화와 사용자 또는 호출자의 재사용 가능 상태를 함께 정의한다.

| 항목 | 계약 |
| --- | --- |
| 발생 조건 | [발생 전 상태·입력·외부 사건·타이밍] |
| 감지와 식별 | [감지 위치·요청/문서/후보 식별자 중 필요한 것] |
| 사용자와 저장 상태 | [화면·응답·저장 자료에 생기는 영향] |
| 보존할 것 | [유지할 자료·정상본·권한 경계 또는 해당 없음] |
| 자동 조치와 상한 | [행동·기한·횟수. 확정/제안/미정 표시] |

| 해제 갱신 사건 | [시간·입력 변경·재접속·응답 등 무엇이 상태를 갱신하는가] |
| 복구 실패 시 종료 | [반복 중단·지원 경로·보존할 최소 진단] |
| 인수 관측 | [오류 유발 → 보존 → 복구 → 해제를 확인하는 방법] |

## 해당할 때 추가할 경계 사례

| 이 기능에 존재하는 조건 | 결정할 계약 |
| --- | --- |
| 저장은 됐으나 응답이 유실될 수 있음 | [결과 불확정 표시·동일 요청 조회/재시도·중복 방지] |
| 최초 실행에 정상본이 없음 | [첫 실패 상태·최초 정상본 생성·이후 복구 기준] |
| 정상본이 손상되거나 저장 결과가 불명확함 | [보존·안전 상태·허용 복구·지원 종료] |
| 취소·화면 이탈·인증 만료·늦은 응답이 있음 | [요청/권한/자원 수명 확인·무효 결과 거부] |
| 다른 구성요소나 실제 장치가 결과를 소비함 | [입력 허용과 실제 사용 가능 조건·관측 범위] |

없는 조건은 삭제한다. 단순 파일 rename을 전원 중단 내구성으로 보거나, 한 후보의 시험을 다른 후보의 성공으로 사용하지 않는다.

## 검증 계획과 근거

| 요구·오류 ID | 전제와 행동 | 예상 관측·판별 기준 | 확인 환경·범위 | 실행 근거 또는 미검증 |
| --- | --- | --- | --- | --- |
| [ID] | [내용] | [무엇을 보고 성공/실패를 구분하는가] | [정적/모의/현재 PC/실제 대상 중 필요한 수준] | [개발 후 기록] |

제품에 존재하는 산출물과 환경만 연결한다. 계획·모의 시험·실제 실행·사용자 위험 수용은 구분한다. 결과 파일을 보존할 때는 다음 실행이 덮어쓰기 전에 필요한 근거를 남긴다.

실행이 필요한 행은 현재 요청·[기획의 작업 권한](project-brief.md#운영-계약과-범위)에 근거해 계획하며, 지침 열람과 검토 대상 코드·검증 스크립트·helper 실행을 별도로 기록한다. 실행이 금지되거나 권한이 미정인 경우 실제 수행으로 쓰지 말고 이유와 미검증 범위를 적는다.
