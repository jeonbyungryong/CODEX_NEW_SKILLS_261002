# 새 프로젝트 템플릿 적용

다음 세 파일을 새 프로젝트에 같은 상대 경로로 복사한다. 스킬 저장소의 루트에는 프로젝트용 `AGENTS.md`를 두지 않고, 배포할 템플릿을 `new-project/`에 보관한다.

별도 [Desktop 수동 검증 기록 양식](desktop-skill-check-results.md)은 [수동 안내](../docs/desktop-manual-skill-check.md)에 따라 필요할 때만 임시 시험 repo **밖**으로 복사한다. 위의 프로젝트 기본 세 파일에 추가해 자동 적용하거나 암묵 선택 대화에 첨부하지 않는다.

| 이 저장소의 파일 | 새 프로젝트의 위치 | 역할 |
| --- | --- | --- |
| [new-project/AGENTS.md](new-project/AGENTS.md) | `AGENTS.md` | 이번 요청에 필요한 스킬 선택과 최소 검토 기준 |
| [new-project/docs/project-brief.md](new-project/docs/project-brief.md) | `docs/project-brief.md` | 목적·범위·운영 계약·개발 순서·미정 결정 |
| [new-project/docs/requirements.md](new-project/docs/requirements.md) | `docs/requirements.md` | 기능 요구·오류 발생과 해제·인수·근거 |

## 적용 요청

새 프로젝트를 연 Codex에 다음 요청을 전달한다.

```text
https://github.com/jeonbyungryong/CODEX_NEW_SKILLS_261002 의
templates/new-project 안의 AGENTS.md와 docs 두 파일을 현재 프로젝트에 적용해줘.
기존 AGENTS.md와 기획·명세가 있으면 유효한 규칙과 내용을 보존해 필요한 항목만 병합하고,
현재 사용자 요청·상위 지침과 충돌하는 항목을 알려줘.
같은 역할의 문서가 이미 있으면 새 문서를 중복 생성하지 말고 참조 경로를 맞춰줘.
우선 프로젝트 목적·이번 산출물·제외 범위와 핵심 사용자 동작을 정리해줘.
미정 정책은 확정하지 말고 담당·결정 시점·그 전 진행 범위를 적어줘.
스킬은 AGENTS.md의 실제 적용 조건이 성립할 때만 사용해줘.
```

`AGENTS.md`는 프로젝트 루트에 놓으면 해당 프로젝트의 지침으로 읽힌다. 기존 `AGENTS.override.md`, 상위·하위 지침의 적용 범위도 확인한다. 글로벌 `~/.codex/AGENTS.md`에 이 템플릿을 설치할 필요는 없다. [OpenAI 공식 AGENTS.md 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md), 확인 2026-10-14.

복사한 템플릿의 `[입력]`과 빈 항목을 프로젝트에 맞게 바꾸고 불필요한 절은 제거한다. 기존 문서 경로를 유지했다면 `AGENTS.md`의 두 링크도 맞춘다. 문서를 단계마다 새로 만들지 말고 실제 결정과 변경을 해당 문서에 갱신한다. 가져온 ref/commit을 기록하면 이후 템플릿 변경과 프로젝트 수정본을 비교하기 쉽다.

## 스킬 선택 조건

| 이번 요청 | 선택 |
| --- | --- |
| 오탈자·색상·배치 수정, 단순 조회, 기존 결과 보고 | 두 스킬 생략 |
| 저장·재시도·복구·해제 동작을 새로 정의하거나 변경·검토 | `specify-failure-recovery` |
| 소스·산출물·시험·승인의 후보 일치와 인계 범위, 근거 충돌·원본 공백·위험 수용·프로젝트 검토 반복 종료 판단 | `review-release-evidence` |
| 한 시험의 시간 예산, 단일 PowerShell 스크립트의 호환성, 개별 native 오류 분류 | 해당 전문 스킬만 선택. 완료·인계라는 표현만으로 `review-release-evidence` 추가 안 함 |
| 오류 복구 계약과 해당 후보의 완료 근거를 함께 판단 | 두 조건에 필요한 부분만 함께 사용 |
| 작은 계산기의 숫자 입력 오류 | 관련 계약을 두 문장으로 작성. 명시적 요청이나 계약 누락이 없으면 스킬 생략 |
| 사용자가 스킬 이름을 직접 지정 | 해당 스킬을 요청 범위만큼 적용 |

단계 이름은 호출 조건이 아니다. 일반 기능 구현에 테스트가 있다는 이유로 릴리즈 검토를 추가하지 않고, 화면 배치 수정이라도 실제 오류·인증·복구 동작에 영향을 주면 그 변경을 기준으로 판단한다. 표는 검토 기준이며 특정 모델의 자동 선택률을 보장하는 실행 장치는 아니다.

두 스킬이 설치되어 있지 않아도 템플릿의 계약은 직접 작성할 수 있다. 설치가 필요할 때만 [기존 설치 안내](../docs/planning-review-skills.md#다른-pc와-프로젝트에-설치)를 사용하고, 개인·프로젝트에 같은 이름을 중복 설치하지 않는다. 이 템플릿 추가에서는 기존 다섯 스킬 본문이나 전역 선택 설정을 변경하지 않는다.

## 기존 프로젝트·동명 스킬에 적용

기존 `AGENTS.md`를 교체하지 말고 현재 요청에 필요한 항목만 병합한다. 기존 기획·명세가 `design/` 등 다른 경로에 있으면 그 경로를 유지하고 링크만 맞춘다. 하위 읽기 전용 지침을 상위 템플릿으로 해제하지 않는다.

같은 이름은 자동으로 합쳐진다고 가정하지 않는다. 발견한 위치별로 `SKILL.md`와 필요한 참조·스크립트의 파일 목록·내용을 비교한다. 전체가 같으면 재설치하지 않는다. 프로젝트 보완이 있으면 보존하고, 본문이 같아도 참조 누락이나 helper 차이가 있으면 완전한 중복으로 판정하지 않는다. 현재 작업에 사용할 완전한 패키지의 명시 경로와 원본 커밋을 기록하고, 파일 보충·업데이트·중복 삭제는 별도 승인 범위에서 결정한다. 경로를 선택했다는 사실은 호스트 검색 우선순위를 시험했다는 뜻이 아니다.

[미설치·기존 지침·동명 패키지 적용 시험](../evals/skill-compatibility-20261015/README.md)에 다섯 스킬의 사례와 보존 확인, 전문 검토에서 발견한 과잉 호출 보완을 기록했다.

## 문서 적용 예시와 확인 범위

[2026-10-15 서브에이전트 적용 시험](../evals/template-application-20261015/README.md)에는 단순 계산기와 오류 복구가 필요한 메모 서비스의 실제 작성 문서가 있다. 초기 명세·라벨 변경·후보별 인계 검토 네 단계에서 필요한 스킬을 선택했으며, 관측된 결함이 없어 본문 규칙은 추가하지 않았다. 이 문서 시험은 앱 실행이나 호스트의 자동 호출률 검증이 아니다.

## 열람·실행 권한 분리 — 2026-10-16

[I4-R1의 문구 보완과 한 번의 재시험](../evals/desktop-implicit-selection-20261016/README.md#7-i4-r1--권한-문구-명확화-후-재시험-1회)을 참고해 기존 세 템플릿만 보완했다.

- `AGENTS.md`: 필요한 지침 열람과 대상 코드·검증 스크립트·helper 실행을 분리하고, 기존 검사 수행 문장을 현재 요청의 실행 승인 범위로 한정한다. 명시적인 셸/도구 금지를 읽기 전용이라는 이유로 해제하지 않는다.
- `project-brief.md`: 이번 작업의 열람·실행 권한을 기록하는 한 행만 둔다. 미정은 기존 결정 표로 연결한다.
- `requirements.md`: 검증 계획에서 현재 요청·기획의 권한을 참조하고 열람과 대상 실행, 미실행 사유를 구분해 기록한다. 별도 승인 표나 반복 체크리스트는 추가하지 않는다.

문안 점검에서는 지침 열람만 허용된 문서 검토가 대상 코드 실행으로 확대되지 않는지, 명시적인 셸 금지를 열람용 명령으로 우회하지 않는지, 승인된 구현·시험에 일괄 실행 금지를 만들지 않는지, 권한이 모호한 해당 작업만 보류하는지를 대조했다. 기존 스킬 적용 조건 표·미설치/동명 보존 규칙은 그대로 유지했다.

이번 작업은 템플릿의 문안·참조·변경 범위 확인이며 새 프로젝트의 실제 적용 시험이나 자동 선택 재시험이 아니다. I4-R1 결과를 템플릿 전체의 행동 검증으로 확대하지 않는다. 과거 I4 원문·충돌 판정·R1 근거, 배포 스킬과 현재 PC의 기존 설치본·설정은 변경하지 않는다. 기존 프로젝트에 적용할 때는 이 절을 별도 전역 규칙으로 복제하지 말고 기존 적용 요청에 따라 필요한 항목만 병합한다.
