# 오류와 복구 계약

오류 코드 목록을 실제 복구 조건으로 연결하는 명세 참고서다. 명세 작성·검토에 사용하며, 이미 승인된 운영 범위를 다시 열거나 제품 수정·재시작·데이터 삭제를 승인하지 않는다. 단순한 입력 오류에는 관련 행만 적용한다.

## 상태의 의미

성공이라는 단어가 가리키는 경계를 먼저 구분한다. 해당 제품에 존재하는 단계만 선택한다.

| 단계 | 이 단계만으로 아직 증명하지 못하는 것 |
| --- | --- |
| 요청 접수 | 처리 또는 표시 완료 |
| 후보 저장·게시 | 실제 사용 가능, 마지막 정상본 갱신 |
| 실제 결과 관측 | 영구 저장, 재시작 복구 |
| 내구 저장 확인 | 호출자에게 응답 도달 |
| 성공 응답 | 다른 후보·기기·실행의 성공 |

마지막 정상본은 단순히 가장 최근 파일이 아니다. 어떤 관측과 저장 확인을 통과해야 정상본이 되는지 제품에 맞게 정의한다. 응답 유실은 확정 실패와 구별한다. 신규 저장소, 정상본 부재, 손상, 결과 불확정도 같은 상태로 합치지 않는다.

## 오류 한 건의 필수 기록

다음 항목을 한 행 또는 짧은 카드로 작성한다. 미정 값에는 결정 담당자, 결정할 단계 또는 날짜, 그 전까지 진행 가능한 범위를 붙인다. 담당자도 정해지지 않았다면 역할 지정부터 미정으로 남긴다. 재시도 수치나 인증 만료 후 허용 행동을 확정값처럼 임의로 채우지 않는다. 제안값은 해당 항목에 제안임과 근거·승인 필요 여부를 표시한다.

- **발생:** 사전 상태, 원인이 되는 사건, 감지 위치, 요청·후보 식별자.
- **영향:** 사용자 화면, 반환 상태, 저장된 자료, 보존해야 하는 정상본.
- **복구:** 자동 조치와 상한, 허용된 운영자 행동, 재시작 종류, 데이터 손실 여부.
- **해제:** 내부 상태가 정상인 조건과 UI가 다시 조작 가능한 조건, 갱신을 일으키는 사건.
- **종료:** 재시도 중단 조건, 관리자 진입 가능 여부, 보존할 최소 진단.
- **검증:** 실패 유발 → 보존 확인 → 복구 행동 → 해제 확인을 잇는 관측과 실행 수준.

시간 만료 자체와 UI 갱신 사건은 다르다. 버튼이 비활성인 동안 그 버튼을 눌러야 상태가 갱신되는 순환 의존을 확인한다. 늦은 callback은 요청 식별자·권한·실제 자원 수명이 아직 유효한지 확인한다.

## 적용 예

안내 화면 A가 정상본이고 B 표시 직후 응답이 유실됐다면 PC는 결과 확인 중으로 표시한다. 재시작 시 A 복귀를 무조건 약속하지 않는다. B의 표시와 내구 저장이 확인되면 B가 정상본일 수 있다. 확인할 수 없으면 제품이 정한 안전 화면과 관리자 경로를 사용한다. 데이터 삭제 없는 복구가 요구되면 초기화는 대안에 넣지 않는다.

최초 설치에는 A가 없으므로 초기 실패 화면과 최초 정상본 생성 방법을 별도로 정의한다. 이 두 경우를 동일한 요청의 실제 consumer 경로에서 확인할 수 있어야 한다. 모듈 테스트와 실제 기기 시험의 증명 범위는 따로 적는다.

## 흔한 누락

`재시도`, `재부팅`, `기존 화면 유지`만 적고 횟수·복귀 대상·해제 관측을 생략하는 것; 파일 rename을 전원 중단 내구성으로 간주하는 것; 예전 프레임이나 다른 요청의 성공을 재사용하는 것; 오류 화면에서 관리 경로에 들어갈 수 없는 것. 발견 시 해당 계약만 보완하고 모든 프로젝트에 복구 프레임워크를 추가하지 않는다.
