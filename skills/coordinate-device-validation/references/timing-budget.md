# 시간 예산과 시험 범위

시간 제한별로 `(시작 사건, 종료 사건, 허용시간, 시각의 관측 출처)`를 적는다. 서로 다른 시작점을 가진 timeout들을 같은 시계로 더하지 않는다. 병렬 수행 근거가 없으면 순차 수행으로 계산한다.

예: 주입창이 시작된 뒤 수집 준비 2초, 사람 반응 4초, 검증 10초, 표시 대기 15초가 순차 실행되면 최대 31초다. 주입창 25초에는 들어가지 않는다. 이는 예제값이며 실제 시험에 고정하지 않는다.

예산이 부족할 때는 다음 대안을 비교한다.

| 대안 | 확인할 조건 | 한계 |
| --- | --- | --- |
| 수집 시작·사용자 준비를 주입 전에 완료 | 준비가 시험 원인이나 상태를 바꾸지 않고 실제 시작 사건을 기록할 수 있음 | 예제의 6초를 모두 제거해도 25초로 여유가 0이다. 실제 조작이 남으면 그 시간도 포함 |
| 검증 종료 등 관측 가능한 사건에 주입 시작을 맞춤 | 명시된 목표가 표시 단계 장애이며, 이전 단계에 주입할 때와 달라지는 노출 조건을 수용할 수 있음 | 원래 목표가 전체 적용 경로라고 추정하지 않는다. 그 목표가 명시된 경우에만 전체 경로 시험과 구분한다. 해당 사건을 알 수 없으면 실행 불가 |
| 주입창 연장 | 장치·복구·운영 조건에서 연장이 허용됨 | 필요한 최소 합계와 별도로 지연·오차 여유를 정함. 임의의 여유 수치를 발명하지 않음 |

실행 순서를 제시할 때 준비 단계와 측정 단계를 분리하고 실제 관측할 사건을 기준점으로 표시한다. 대안의 전제조건을 확인하지 못했다면 조건부 제안으로 남긴다. 지원되지 않는 자동 트리거가 존재한다고 가정하지 않는다.

최악 예산 부족은 주어진 지연 범위 전체를 보장하는 절차가 성립하지 않는다는 뜻이다. 모든 개별 실행이 반드시 실패하거나 timeout을 관측할 수 없다는 뜻으로 확대하지 않는다.

같은 오류 코드가 여러 실패 분기를 가리키면 경과시간만으로 timeout을 확정하지 않는다. 분기를 구별할 로그나 상태 관측이 없으면 결과는 판정 불가다. 반복 횟수는 판별력을 대신하지 않는다.
