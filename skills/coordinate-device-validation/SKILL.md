# 사용자 참여 실기시험 조율

사용자가 장치를 조작하고 agent가 명령·수집을 담당하는 시험에서, 실행 가능한 짧은 행동 안내와 판별 가능한 결과를 만든다. 제공된 프로젝트의 조작법과 승인 범위를 사용한다.

## 실행 카드

현재 목표 주장 하나와 정상 기준·후보를 확인하고, 사용자에게 필요한 항목만 짧게 전달한다.

> **준비:** 어느 기기의 어느 화면·연결 상태인가. 이전 화면 유지 지시가 끝났다면 이를 정정한다.
>
> **행동:** 누가 무엇을 언제 몇 회 하는가. 시작 조건이 미충족이면 다음 동작을 보류한다.
>
> **관측:** 사용자가 알려줄 화면·상태와 agent가 수집할 응답·로그는 무엇인가.
>
> **종료:** 재시도하지 않을 조건과 이미 승인된 복귀 절차는 무엇인가.

사용자가 이미 확인한 유효한 준비를 반복 질문하지 않는다. 준비 후 연결·화면·후보가 바뀌면 바뀐 조건을 새로 확인한다. 알 수 없는 버튼 이름·시간 제한은 만들지 않는다.

## 시간 제한이 있을 때

[시간 예산](references/timing-budget.md)을 읽는다. 각 제한시간의 시작 사건과 끝 사건을 표시하고 사람 반응·수집·검증·표시 대기의 실제 순서를 합산한다. 채팅 메시지를 정밀한 시작 시각으로 사용하지 않는다.

예산이 부족하면 아직 실행하지 않는다. **준비를 측정창 밖으로 옮길 수 있는지, 주입 시작점을 검증 단계 뒤로 옮겨도 같은 주장을 시험하는지, 허용 창 연장이 가능한지**를 각각 검토한다. 대안마다 바뀌는 조건과 증명 범위를 짧게 적는다. 불가능한 설계를 말만 바꿔 가능한 것으로 처리하지 않는다. 추가 코드·수집기 개발은 실제로 필요하고 요청 범위에 있을 때만 진행한다.

## 결과

실행 조건·후보·관측 출처·결과·현재 복귀 상태를 남긴다. 사용자 실물 관측과 PC 응답은 별도 근거다. 목표 분기를 구분하지 못하거나 시간 조건을 놓친 표본은 판정 불가로 기록한다. 복귀 성공은 고장 원인 확정과 별개다. 필요한 결과를 얻으면 같은 시험을 더 반복하지 않는다.
