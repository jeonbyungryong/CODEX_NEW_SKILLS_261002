# 검증 결과와 알려진 한계

2026-10-02 · 지침 패키지 v0.1. 이 문서는 응답 생성 검증이지 실제 기기 수락시험 보고서가 아니다.

## 결론

`coordinate-device-validation`을 **사람·agent 인계 및 시간 제한이 있는 실기시험 절차 검토용으로 제한적 채택**한다. 입증된 비교상 이점은 시간 예산 대안의 전제·관측 요건을 더 구체적으로 설명한 점이다. 단순 시간 합산, 기본 진단, 일반 기획 전체의 성능 향상을 주장하지 않는다.

## 후보 선별

| 후보 | 기준선 표본 | 판단 |
| --- | --- | --- |
| S1 범위·수용 기준 | 이전 7개 충족 | 생성 보류 |
| S2 실행 계층 진단 | 이번 8개 충족 | 생성 보류 |
| S3 실기 협업 | 이번 9개 중 8개 충족, 1개 대안 설명의 경미한 부족 | 좁힌 후보 비교 진행 |
| S4 재개 지원 | 이번 5개 충족 | 생성 보류 |

S3 최초 부족 사례에서도 계산과 실행 보류는 맞았다. 창 연장이라는 타당한 대안도 제시했다. 단순히 상세 체크리스트를 못 채웠다고 안전 실패로 과장하지 않았다. 클릭 횟수 안내는 독립 검토에서 문맥상 단회로 인정했고 실패로 세지 않았다.

이번 선별 22회는 독립 문맥으로 수행하고 별도 채점자가 원문을 검토했다. 이전 S1 7회와 합쳐 원래 설계의 33개 전체를 완료했다고 주장하지 않는다. 표본들이 전체 문제 공간을 대표하지도 않는다.

## 동일 입력 A/B

2026-10-02, 실행 trace상 GPT-6 Astra / High. 모델·추론 별도 override 없음. 후보 직접 지정 전후 각각 5개 새 문맥, 사전 고정 기준과 별도 채점. [입력·판정 기준·응답 원문](../evals/README.md), [원수치](../evals/measurements.json).

| 관측 | A: 기존 환경 | B: 후보 직접 지정 |
| --- | --- | --- |
| 31>25 계산, 현 조건 보류 | 5/5 | 5/5 |
| 실제 실행·지원 기능·허가 발명 없음 | 5/5 | 5/5 |
| 유효한 창 연장 등 대안 | 5/5 | 5/5 |
| 남는 조작·범위·동기화·관측 조건을 구체화 | 해당 상세 묶음 없음 | 5/5 |
| 적용 조작 이동의 시험 동일성을 명시적으로 확인 | 명시 없음 | 4/5 |
| 평균 응답 문자수 | 608 | 897.6 |
| 외부 도구 호출 수 합계 | 10 | 10 |
| 그 호출 안의 읽기 명령 수 합계 | 10 | 14 |

문자수는 LF 줄바꿈, Markdown 포함, 끝 줄바꿈 제외 UTF-16 코드 단위다. 토큰수가 아니다. B는 평균 289.6자 더 길었고 읽기 부담도 있었다. 사용자 실제 시간·비용 절감은 측정하지 않았다. Q2/Q3 기준이 후보에 유리할 가능성, 평가자의 조건 인지, 작은 단일 사례 표본이라는 한계가 있다. 통계적 우월성을 주장하지 않는다.

## 추가 사례와 수정

다음 4개는 각 1회이며 부모가 고정 기준에 대조했다. 모두 GPT-6 Astra / High, 실제 기기 조작 없음.

| 사례 | 관측 결과 |
| --- | --- |
| 다른 숫자: 40초 창, 순차 3+5+8+12 | 28초·계산상 12초 여유, 오차 예산 미확정과 실제 PASS를 구분 |
| 준비 완료, 사람4·검증10 병렬 후 표시15 | max(4,10)+15=25, 여유0. 병렬을 중복 합산하지 않음 |
| 관리자 유지 지시 후 송출 복귀가 필요한 다음 단계 | 기존 유지 지시 해제, 송출 복귀 확인만 요청, PC 적용은 아직 보류 |
| 단순 오타 수정, metadata만 제공 | 후보 비선택. 본문 읽기나 실기 절차 강요 없음 |

마지막 사례는 metadata 수준 선택 판단일 뿐 실제 설치 환경의 자동 발견 검증이 아니다. 나머지 3개는 후보를 명시 지정했다.

독립 A/B 검토에서 B가 원래 목표를 ‘전체 적용 경로 시험’으로 단정하는 표현상 한계를 지적했다. 실제 입력은 표시 timeout만 명시했다. 참조 문서를 1회 수정해 원 목표를 추정하지 않도록 했고, 최악 예산 부족을 모든 개별 실행 실패로 확대하지 않도록 명시했다. 위 A/B 10회와 추가 4회는 이 수정 전 결과이며, 수정 후 전체 반복 비교로 표시하지 않는다. 수정 후 동일 입력의 [새 문맥 표적 회귀 R1](../evals/responses/R1.md) 1회에서는 원 목표를 전체 경로로 단정하지 않고, 빠른 개별 실행의 관측 가능성과 최악 조건 보장을 구분했다. 부모가 해당 수정 기준에 대조했으며 전체 반복 비교를 다시 수행한 것은 아니다.

## 구조·게시 검사

- 기본 frontmatter 이름·설명 형식/길이와 문서 링크·참조 경로의 별도 읽기 검사에서 오류가 없었다. 본문과 참조는 각각 Markdown 파일이며 별도 실행 프로그램이 없다. [후보 전후 파일 해시](../evals/versions.json)를 보존한다.
- 시스템 `quick_validate.py`는 실행을 시도했으나 이 환경에 PyYAML이 없어 시작 단계에서 중단됐다. 공식 검증기 PASS로 기록하지 않는다. 의존성 설치나 런타임 변경은 하지 않았다.
- 게시 목록을 지침·사용/설계/검증 문서·가상 응답으로 한정했다. 파일 종류/링크/경로·비밀 패턴 검사와 본문 검토를 수행했다. 개인 절대 경로, 장치 로그, APK, 키, 인증정보는 포함하지 않는다. 패턴 검사는 모든 비밀 유출을 탐지한다는 보증이 아니다.
- 공개 저장소의 기존 `.gitignore`와 부모 이력은 보존한다. MAIN은 비강제 PR 병합 뒤 실제 원격 상태로 확인한다.

## 미검증 범위

최종 읽기 전용 독립 검토에서는 병합 차단 결함을 발견하지 못했다. 검토자가 지적한 B1의 ‘동일성 검토’ 과대 집계는 위 표에서4/5로 정정했다. 검토 이후 추가한 전후 해시 JSON과 R1 최종 수락·원격 게시 확인은 메인 작업자가 담당하며, 독립 검토가 이를 모두 인증했다는 뜻은 아니다.

실제 장치, 설치 후 자동 선택, 다중 Skill 상호작용 전체, 장기 세션·압축 복구, 다른 모델에서의 효과, 모든 33개 설계 사례, 실제 비용·시간 절감은 미검증이다. 재부팅/신원 확인을 포함한 Skill의 모든 문장을 각각 독립 실기로 검증한 것은 아니다. 효과가 필요한 사례에서만 사용하고 불필요한 응답 길이·준비 요구가 늘면 축소하거나 사용을 보류한다.

## v0.2 후속 검증: PowerShell 인계

초기 v0.1의 실기 협업 평가는 위에 그대로 보존한다. 후속 `verify-powershell-handoff`는 별도의 모델·문항·실험이며 기존 결과와 합산하지 않는다.

GPT-6.1 Sol / High의 같은 입력·새 문맥 5+5회에서 JSON 컬렉션 결함 해결은 적용 전 0/5, 적용 후 5/5였다. 나머지 세 기준은 양쪽 5/5였다. 그룹 표시를 숨기고 순서를 바꾼 별도 채점이 이를 확인했다. 4개 추가 사례는 각 1회, 부모의 의미 검토로 충족했다. 실제 PowerShell 5.1.26100.9444와 7.6.5의 기초 시험은 각각 17개 통과했다.

[상세 범위·비평](powershell-handoff.md), [응답·사전 기준·기초 시험](../evals/powershell-handoff/README.md)을 보라. 실행 시험은 합성 도우미를 사용한 기초 동작 검증이며 운영 도우미나 전체 사용자 인계 검증이 아니다. 기존 v0.1보다 전반적으로 더 효율적이라는 주장은 하지 않는다.
