# 설계와 채택 기준

2026-10-02. 장기 프로젝트의 기획·명세·진단·기기시험·인계 경험을 재사용 가능한 작업 방법으로 추출한다. 공개본의 사례는 가상화했으며 원본 장치 로그나 회사 운영 데이터는 포함하지 않는다.

## 후보와 중복 검토

| 후보 | 다루는 문제 | 기존 기능과의 관계 |
| --- | --- | --- |
| scope-to-acceptance | 승인 범위와 시험·수용·진행률 혼동 | 기본 분석·보고 능력이 충분한 사례에서는 추가하지 않음 |
| diagnose-execution-layers | 도구 연결, 전송, 업무 응답, 실제 표시 혼동 | 일반 디버깅 방법 전체를 복제하지 않음 |
| coordinate-device-validation | 사람이 조작하고 agent가 수집하는 시험의 인계 누락 | 기기 접근 도구를 대체하지 않으며 필요한 행동 안내에 집중 |
| resume-from-decisions | 최신 승인과 오래된 상태의 혼동 | 프로젝트의 재개 문서·메모리를 대체하는 별도 시스템을 만들지 않음 |

특정 제품용 release-gate는 기존 승인 범위와 증거를 확인하도록 이미 구성되어 있어 이번 저장소로 복제하거나 수정하지 않는다.

## 판단 원칙

실패 원인 가설, 사용자 보고, 실제 도구 관측, 미실시는 구분한다. 운영상 위험을 수용했다고 미실시 시험을 PASS로 바꾸지 않는다. 특정 프로젝트의 리셋 허용 기준·포트·기기 ID·PIN·모델 이름은 범용 Skill 규칙으로 고정하지 않는다.

Skill 본문은 사용 조건과 판단에 필요한 최소 내용으로 구성한다. 입력에 없는 버튼 이름·시간 제한·권한은 만들지 않는다. 이미 받은 사용자 승인은 유지하며 새로운 범위가 필요할 때만 필요한 확인을 한다.

## 검증 방식

기존 환경만 사용하는 기준선을 먼저 관측하고, 구체 누락이 확인된 후보만 생성한다. 후보 비교에서는 같은 입력·모델·추론 설정을 유지하며 이력 없는 실행을 사용한다. 정답 기준은 실행자에게 전달하지 않는다. 응답 생성, 도구 실행, 자동 발견, 실제 기기 성공은 별도 검증 수준이다.

최초 선별은 사례별 한 번이다. 효과 비교에 들어가면 대표 사례의 A/B를 각각 5회 수행한다. 표본이 작으므로 성능 보장이나 시간 절감률을 제시하지 않는다. 개선이 없으면 후보를 축소하거나 보류한다.
