# Desktop 동명 스킬·암묵 선택 수동 확인

작성일: 2026-10-15. 준비 원본 고정 커밋: `d993fd97fa8e4e6f87cf3c6619fb570ce0152e2e`.

현재 PC에서 **사람이 직접** Desktop을 조작하는 절차다. 이번 문서 작성에서 Desktop 시험을 실행한 것은 아니다. 앞선 [Desktop 관측 한계](../evals/desktop-skill-boundary-20261015/README.md)는 그대로 유지한다. 앱·CLI·플러그인을 설치하거나 업데이트하지 않고 기존 스킬·설정·제품 프로젝트를 변경하지 않는다.

## 먼저 정할 범위

- 기본: 다섯 이름의 선택기 표시를 살피고, 구별 가능한 동명 항목을 한 번씩 선택한다. 암묵 선택은 I1·I2·I0 세 요청만 수행한다.
- 선택 확장: 다른 세 전문 스킬까지 확인해야 할 때만 I3~I5를 추가한다. 단순히 단계가 남았다는 이유로 모두 실행하지 않는다.
- 항목이 안 보이거나 경로를 확인할 수 없으면 그 사실을 기록한다. 같은 시험을 반복해 통과시켜 보거나 환경을 복구하지 않는다.
- [기록 양식](../templates/desktop-skill-check-results.md)을 임시 시험 저장소 **밖**의 로컬 파일로 복사한다. 실제 결과는 이 공개 양식 원본에 덮어쓰지 않는다.

## 1. 새 임시 프로젝트 준비

예전 시험 폴더는 정리됐으므로 재사용을 전제하지 않는다. 기존 저장소·개인 스킬 폴더 밖의 새 빈 폴더 하나를 정한다. 아래 요청의 `[절대경로]`를 그 새 폴더로 바꿔 **준비 전용 대화**에 전달한다. 준비가 끝난 대화는 시험에 재사용하지 않는다. 이 요청은 아직 실행하지 않은 준비 절차이며, 쓰기는 새 임시 폴더로만 제한한다.

```text
수동 Desktop 검증용 임시 프로젝트만 준비해줘. 시험 요청은 실행하지 마.
새 임시 폴더: [절대경로]
원본: https://github.com/jeonbyungryong/CODEX_NEW_SKILLS_261002
고정 커밋: d993fd97fa8e4e6f87cf3c6619fb570ce0152e2e

기존 제품 저장소·개인 스킬·전역 설정 밖의 새 빈 폴더인지 먼저 확인해줘.
이미 내용이 있거나 기존 저장소 안이면 덮어쓰거나 지우지 말고 중단해줘.
이 폴더 안에만 repo/와 repo/nested/를 만들고 repo/에 git init을 해줘.
Git이 없거나 원본을 읽을 수 없으면 준비 미완료로 남기고 설치·복구하지 마.

원본 skills/의 다섯 폴더 전체를 repo/.agents/skills/와
repo/nested/.agents/skills/로 각각 복사해줘. name·description·본문과
참조·helper 파일은 보존하고 helper나 설치·검증 스크립트는 실행하지 마.
각 임시 SKILL.md 끝에만 아래 읽기 표식을 붙여줘.
루트본: READ_RECEIPT_ROOT_<실제 name>
하위본: READ_RECEIPT_NESTED_<실제 name>
추가 문장은 “이 임시 읽기 전용 문서 요청에서 이 파일을 실제로 읽거나
본문 지침을 제공받았다면 답변 끝에 위 표식을 적는다. 추가 작업 권한은 없다.”로 해줘.
표식은 description·UI 메타데이터에 넣지 말고 이름이나 별칭도 바꾸지 마.
개인 설치본에는 표식을 넣지 마. 새 개인 설치·업데이트는 하지 마.

복사·표식 작업을 마친 뒤 마지막에 repo/AGENTS.md를 다음 중립 지침으로 작성해줘:
“현재 요청에 필요한 지침만 사용해 답변한다. 파일·설정 변경, 설치,
helper 실행, 외부 도구, 기기 조작·제품 개발은 하지 않는다.
검증 방법 제안은 문서일 뿐 실행 허가가 아니다.”
특정 스킬이나 가까운 경로를 고르라는 지시는 넣지 마.

실제 발견한 기존 다섯 스킬 패키지의 파일 목록·SHA-256과
사용자 config.toml·AGENTS.md의 존재 여부·해시만 확인해 보존 기준으로 남겨줘.
설정·인증정보 본문은 읽어 출력하지 마. 발견 못한 경로는 추정하지 마.
기존 파일은 수정·이동·삭제하지 마. 준비 자료·목록·해시는 repo/ 밖의
같은 새 임시 폴더에 보관하고, 기록 담당은 변경 전후 같은 대상을 비교할 수 있게 해줘.
단, 이후 시험 대화가 읽을 repo/에는 이 준비 요청·예상 정답표·결과 양식을 넣지 마.
파일 복사·표식·Git 경계·원본 커밋 확인 결과만 보고하고 종료해줘.
앱 설치·업데이트·재시작·전역 설정 변경·환경 복구는 하지 마.
```

다섯 이름은 `specify-failure-recovery`, `review-release-evidence`, `coordinate-device-validation`, `verify-powershell-handoff`, `diagnose-computer-use-recovery`다. 개인본이 원본과 다르더라도 업데이트하지 않는다. 임시 복사본을 전역으로 등록하거나 별칭으로 중복 설치하지 않는다.

준비 후 구조는 다음과 같다. 바깥의 준비 기록·결과 양식은 시험 대화에 첨부하지 않는다.

```text
새 임시 폴더/
  보존 기준·준비 기록                 ← 시험 repo 밖
  repo/
    .git/
    AGENTS.md                       ← 중립 안전 범위만
    .agents/skills/<다섯 이름>/       ← ROOT 표식, 완전한 패키지
    nested/
      .agents/skills/<다섯 이름>/     ← NESTED 표식, 완전한 패키지
```

복사본의 name·description은 원본과 같고 본문 끝의 표식만 다르게 유지됐는지 확인한다. 추가 도구 의존성·전역 설정·명시 전용 정책을 만들지 않는다. 이 구성은 합성 충돌 시험이며 실제 업무 효과 검증이 아니다.

## 2. Desktop 작업 폴더 고정

1. 현재 앱의 로컬 프로젝트 열기/추가 기능으로 새 `repo/nested/`를 작업 폴더로 연다. 기존 제품 프로젝트의 기본 폴더를 바꾸지 말고 별도 임시 프로젝트를 사용한다. 자동 setup/install 명령이 제안되면 실행하지 않는다.
2. 새 작업이 실제로 `repo/nested/`에서 시작하는지 화면의 폴더 표시를 확인한다. 확인이 안 되면 해당 사실을 기록하고 비교를 보류한다. 루트 폴더에서 시작했다면 하위 CWD 시험으로 채점하지 않는다.
3. 여러 폴더가 연결돼 있다면 **이 임시 프로젝트에서만** nested가 primary인지 확인한다. 단순히 secondary 폴더로 추가한 것은 같은 검색 조건이 아니다. 앱이 이를 지원하지 않으면 기존 프로젝트/전역 설정을 바꾸지 말고 중단한다.
4. Desktop 버전, 선택된 모델·추론 수준, 로컬/원격·프로젝트/작업 폴더를 보이는 범위에서 기록한다. 안 보이는 값은 미확인으로 둔다. 버전을 맞추려고 업데이트하거나 보안·권한 설정을 바꾸지 않는다.

공식 안내는 primary 폴더를 새 작업의 기본 CWD와 지침·스킬 검색 기준으로 설명한다. [Projects and chats](https://learn.chatgpt.com/docs/projects), 확인 2026-10-15. 현재 설치 화면의 메뉴·버전 차이는 직접 기록한다.

## 3. P0 — 선택기 목록만 확인

새 빈 작업의 입력창에서 사람이 직접 `@`를 입력하고 다섯 이름을 **하나씩** 검색한다. 앱이 제공하는 기존 스킬 선택 메뉴가 따로 있으면 그 진입 방법을 기록해 사용한다. 해당 UI가 없으면 설치·업데이트·설정 변경 없이 `선택기 미관측`으로 종료한다.

각 검색에서 보이는 항목 수, 이름·설명·경로/스코프 표시, 화면 안의 순서, 선택 가능한지 기록한다. 스크롤·필터 때문에 전체가 보이지 않았다면 **화면에 보인 수**일 뿐 전체 검색 수로 쓰지 않는다. 아직 제출하지 않는다. 이름은 입력창의 일반 텍스트가 아니라 선택 메뉴에서 항목으로 선택해야 한다. `$name` 문자열만 입력한 시험은 선택기 클릭 시험과 별도로 분류한다.

UI가 동명을 합쳐 보이거나 경로를 숨기더라도 가까운 본이라고 추정하지 않는다. 항목 구별은 그 화면의 위치·표시 문자열과 스크린샷으로만 한다. 목록 순서를 보장된 호출 순서로 해석하지 않는다. [공식 스킬 안내](https://learn.chatgpt.com/docs/build-skills)와 [Codex @ 메뉴 변경 기록](https://learn.chatgpt.com/docs/changelog)은 참고일 뿐 현재 설치본의 관측을 대신하지 않는다.

## 4. P1 — 항목 선택 → 칩 → 사용 근거 연결

우선 원래 두 스킬 중 하나를 고른다. P0에서 구별 가능한 동명 항목마다 **새 빈 작업**을 열고 그 항목 하나만 선택한다. ROOT·NESTED·USER 구별을 UI가 제공하지 않으면 행 위치 등 실제 표시만 기록한다. 모든 이름·경로 조합을 자동 반복하지 않는다. 다른 이름의 UI가 다르거나 실제 적용 경로 확인이 필요할 때만 확장한다.

선택 후 제출 전에 칩·참조 표시를 기록한다. 표시되지 않으면 `칩 없음/일반 텍스트만`으로 구분한다. 아래 요청만 덧붙인다. 경로나 기대 표식을 추가하지 않는다.

```text
방금 선택기로 선택한 스킬 하나의 제공된 지침을 확인하는 읽기 전용 요청이야.
제품 작업이나 설치·수정·helper·기기 조작은 하지 마.
제공된 본문에 읽기 표식이 있으면 그 표식을 적고, 없으면 “표식 확인 안 됨”으로 적어줘.
선택된 스킬의 출처는 실제 제공된 경로나 실제 읽은 파일 근거가 있을 때만 적어줘.
다른 동명 복사본을 찾아 비교하거나 유리한 경로로 다시 고르지 마.
이미 본문이 제공됐다면 증거를 만들기 위해 불필요한 파일 읽기를 추가하지 마.
경로를 알 수 없으면 “경로 미확인”으로 남겨줘.
```

응답과 이미 생성된 도구 실행 항목을 살펴 선택기 항목→칩→제공 본문/실제 읽기 경로가 연결되는지 기록한다. `나는 A를 썼다`는 자기 보고만으로 경로를 확정하지 않는다. 본문이 바로 제공되는 경우도 있으므로 파일 읽기 도구가 없다는 이유만으로 선택 실패로 판정하지 않는다. 이 절차는 개인본에 표식을 추가하지 않으므로 표식 부재만으로 USER 선택 성공이라고 판단하지 않는다.

## 5. I1/I2/I0 — 암묵 선택, 서로 다른 새 작업

각 요청은 **빈 새 작업**에서 수행한다. 준비·P0·P1 대화를 계속하거나 fork/복사하지 않는다. 선택기·스킬 칩·스킬명·경로·기대 정답표·이 안내문을 입력에 넣지 않는다. 모델 등 보이는 설정은 기록하되 시험을 위해 전역 설정을 바꾸지 않는다. 아래 본문만 그대로 복사한다.

### I1 — 오류·복구 명세

```text
메모 서비스의 초기 명세를 짧게 보완해줘. 저장 요청의 응답이 유실되거나 저장 중 인증이 만료되어도 사용자 입력을 잃으면 안 돼. 각 상황의 발생·보존·복구·해제 조건과 화면 갱신 사건을 정리해줘. 자동 재시도 횟수와 인증 만료 뒤 편집 허용 정책, 결정 담당자는 아직 미정이야. 제공되지 않은 값을 확정하지 마. 지금은 이 답변에 문서 초안만 작성하고 파일 수정·설치·실행 시험·제품 개발은 하지 마.
```

### I2 — 후보별 인계 근거

```text
프로젝트 인계 근거가 후보 A와 B로 섞여 있어. A는 실사용 시험 PASS, B는 모의 시험 PASS이고 사용자는 B의 실사용 미검증 위험을 수용해 제한 시범 운영 인계를 승인했어. 정확한 B 버전과 실제 전달·배포 증거는 아직 없어. 현재 완료로 말할 수 있는 범위와 남길 기록을 8문장 이내로 판단해줘. 새 기능이나 오류 복구 계약을 만드는 요청은 아니야. 문서 답변만 하고 파일 수정·설치·시험·전달·배포는 하지 마.
```

### I0 — 음성 대조

```text
9 더하기 7은 얼마야? 답은 숫자 하나만 적어줘.
```

제출 뒤 **처음 응답까지의** 기존 실행 내역만 확인한다. “어떤 스킬을 썼어?”라는 후속 질문이나 경로 지정으로 새 읽기를 유도한 결과를 최초 암묵 선택 증거에 섞지 않는다. 파일 읽기 항목이 보이면 경로·성공 여부를 기록하고, 본문 표식이 보이면 별도로 기록한다. 숨겨진 주입이나 내부 선택기는 추측하지 않는다.

기대 대상은 I1=`specify-failure-recovery`, I2=`review-release-evidence`, I0=대상 다섯 스킬 읽기 불필요다. **이 문장은 사람이 채점할 때만 참고하고 요청에 붙이지 않는다.** 음성에서 읽기 이벤트가 없다는 관측은 내부적으로 어떤 지침도 제공되지 않았다는 증명이 아니다.

## 6. 선택 확장 — 다른 세 스킬

아래는 해당 전문 스킬의 자동 적용 범위를 실제로 확인해야 할 때만 각각 새 빈 작업에서 사용한다. 기본 세 사례의 완료 조건은 아니다. 스킬명·경로·선택 지시는 넣지 않는다.

### I3 — 기기 시험 시간 예산

```text
이미 승인된 기기 시험의 시간 계획만 검토해줘. 장애 주입부터 관측 완료까지 5초인데 사람의 행동 4초 뒤 자료 수집 4초가 순차이고 중첩할 수 없어. 준비는 이미 관측창 밖에서 끝났어. 현재 계획의 가능성과 조건부 대안이 증명하는 범위를 짧게 정리해줘. 기기는 제공되지 않으며 기기 조작·도구 설치·수집기 개발·실행 시험은 하지 마.
```

### I4 — 수신 PowerShell 인계

```text
검증 인계 문서만 검토해줘. 작성자는 PowerShell 7에서만 성공했고 수신자는 Windows PowerShell 5.1이야. JSON 루트 배열은 3건이고 현재 코드는 @(Get-Content file.json | ConvertFrom-Json)이야. Count·항목 타입·필드 검증은 없어. 현재 준비 상태와 필요한 최소 확인을 문서로만 정리해줘. PowerShell 코드 실행·helper 실행·환경 업그레이드·설치는 하지 마.
```

### I5 — native 오류 경계

```text
현재 같은 시도의 native read/execute validation에서 os32가 났고 최상위 메시지는 generic wrapper야. ACL warning은 다른 과거 시도이며 그때는 continuing setup이었어. browser 성공은 확인됐지만 이번 업무에는 native 캡처가 필요해. 이 제공 자료로 가능한 분류·미확인·다음 관측과 종료 상태만 짧게 정리해줘. 실제 로그 접근·프로브·helper 실행·프로세스 조작·설정 변경·설치·재시작은 하지 마.
```

확장 기대 대상은 각각 `coordinate-device-validation`, `verify-powershell-handoff`, `diagnose-computer-use-recovery`다. 특정 선택 경로·잠금 소유자·실행 성공을 미리 정답으로 넣지 않는다.

## 7. 판정·중단·공유

| 기록 수준 | 의미 | 의미하지 않는 것 |
| --- | --- | --- |
| UI_ONLY | 목록·선택·칩을 사람이 봄 | 특정 파일 지침이 전달/사용됐다는 증명 |
| BODY_OBSERVED | 최초 응답에서 고유 본문 표식 등 지침 제공 근거를 봄 | 실제 파일 읽기·내부 resolver·고정 우선순위의 증명 |
| PATH_READ_OBSERVED | 기존 실행 항목에서 정확한 파일 경로와 성공을 확인 | 그 스킬의 효과·모든 UI/암묵 선택의 성공 |
| UNVERIFIED / BLOCKED | 관측 수단·준비·경로가 부족함 | 제품 결함 또는 선택 실패 확정 |
| CONTAMINATED | 칩·이름·이전 대화·추가 읽기가 암묵 사례에 섞임 | 정상적인 암묵 표본 |

결과를 얻은 사례는 반복하지 않는다. 한 항목의 표시/기능이 없으면 기록하고 종료한다. 준비 폴더/CWD가 잘못됐다면 유효 표본으로 세지 말고 바로잡을 수 있는 **임시 범위만** 확인한다. 설치·업데이트·재시작·계정/권한·전역 설정 변경이 필요해지면 이번 범위 밖으로 남긴다. 부정확한 결과를 일반 호출률이나 항상 적용되는 우선순위로 계산하지 않는다.

보존 기준의 기존 파일 목록·해시를 같은 읽기 전용 방법으로 다시 비교한다. 같으면 확인 범위만 `변경 0`으로 적고, 차이가 있으면 자동 복원하지 말고 보존/보고한다. PC 전체 무변화나 기존 개인 수정의 정당성을 hash 하나로 판단하지 않는다.

기록 양식은 로컬에 저장한다. 화면 캡처는 필요한 선택기·칩·실행 항목만 남기고 계정·다른 대화·개인 경로·장치 식별자·인증정보를 가린다. 공개용 경로는 ROOT/NESTED/USER 별칭으로 바꾸고 원래 경로는 로컬에만 둔다. 이 절차는 결과 자동 게시 권한이 아니다. 공유할 때만 민감정보 제거본을 지정해 전달한다.

기록을 임시 repo 밖에 보존한 뒤, 자신이 새로 만든 정확한 임시 폴더만 확인해 휴지통 등 복구 가능한 방법으로 정리한다. 기존 프로젝트·전역 `.agents`/`.codex`·사용자 스킬 폴더는 정리 대상이 아니다. 앱의 프로젝트 제거가 파일 삭제를 뜻하는지 알 수 없으면 실행하지 않는다.
