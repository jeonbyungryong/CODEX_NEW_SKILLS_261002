# Computer Use 검토 결과와 재사용할 판단

2026-10-02 KST · 조사 보고서. 설치 가능한 새 Skill이나 브라우저 복구 프로그램이 아닙니다.

## 결론

Computer Use 특화 Skill은 **생성 보류**입니다. 과거 작업에서 연결·표시·명령 실행·정리 문제가 섞여 있었지만, 후속 기준선에서 추가 Skill이 필요한 명확한 반복 판단 실패는 확인하지 못했습니다. 필요성이 없다고 입증한 것은 아닙니다. 기존 Skill 2개를 유지하며 같은 성공 시험을 새 근거 없이 반복하지 않습니다.

Skill은 반복할 판단·절차를 설명하는 지침이고, 실제 연결·인증·행동은 제공된 도구와 실행 환경에 달려 있습니다. Skill 작성이나 사용자 승인만으로 제공되지 않는 API 또는 도구의 금지 동작을 활성화하지 않습니다. [OpenAI Skills 개념](https://developers.openai.com/plugins/concepts/skills), [작성 안내](https://developers.openai.com/plugins/build/skills).

## 확인된 사실

아래 과거 실시험과 평가의 보존 기록을 다시 검토했습니다. 이번 정리에서 재실행한 결과가 아닙니다. Windows UI 초기화·목록 조회만 이번 정리 중 새로 수행했습니다.

| 계층 | 관측 범위 | 입증하지 않은 것 |
| --- | --- | --- |
| Edge 연결 | 재부팅 후 연결 목록·새 빈 탭 읽기 성공 | 과거 연결 부재의 원인, 재부팅의 보편적 효과 |
| Edge localhost | 격리 run 1회: 읽기·입력·단회 적용·PENDING·COMPLETE·새 탭 재확인. 서버 기록과 적용 1회 일치 | 앱 전체 재시작, CDP 전송 시간 초과·응답 유실, 운영 태블릿 |
| Chrome localhost | 별도 격리 run 1회: 읽기·입력·단회 적용·대기·완료·새 탭 확인 | 모든 프로필 연결, Chrome 전체 재시작, 파일 선택·업로드·다운로드 |
| Chrome 표시 | 일부 제목·상태·JSON 표시가 한국어로 변환됨. 같은 run의 원본 기록은 영어와 적용 1회 유지 | 변환 제공자·설정 원인, 데이터 손상 |
| PowerShell 명령 실행 | 직접 생성한 자식 4개의 서로 다른 종료 경로 확인. 별도 입력 시험에서 non-TTY stdin 거부, TTY stop CRLF의 ACK·종료 코드 0 확인 | 터미널 창의 UI 조작, 과거 교차 세션 종료 오류의 재현·해결 |
| 조회 권한 | CIM 조회는 기본 실행 범위에서 거부, 승인된 실행 범위에서 성공 | 내부 보안 규칙의 원인, 전역 권한 확대 필요성 |
| 지연된 종료 확인 | 시험 서버 정리 중 즉시 완료 출력이 없었으나 이후 listener 없음과 STOP·종료 코드 0 확인. 보호 조건에 따라 외부 kill 미실행 | 여러 입력 중 정확한 종료 유발 입력, 모든 종료 실패 해결 |
| 현재 Windows UI | 공식 `@oai/sky` 모듈 초기화와 `list_windows()` 응답 성공 | 화면 캡처·텍스트 읽기·클릭·입력, 브라우저 확장 연결, 제품 복구 |

현재 창 목록은 과거 브라우저 확장 연결 목록과 다른 채널입니다. 실행 파일명 패턴으로 대상이 매칭되지 않아도 브라우저 미설치·전체 미실행·권한 차단의 증거로 쓰지 않습니다. 과거 특정 도구가 안내한 “네이티브 비활성”도 현재 Windows UI 전체 불가로 일반화하지 않습니다.

## Skill 필요성 평가와 비평

- 엄격 권한·포트 평가: 시나리오 2종, 새 문맥 6개, 응답 13개. 초기 권한 응답 5개는 독립 검토에서 충족했습니다. 후속 응답 모두를 독립 검증한 것은 아니며 13개 독립 실시험으로 세지 않습니다.
- 표시 변환·stdin·지연 종료의 좁은 후속 평가: 새 문맥 3개, 각각 1회. 독립 판정은 충족 2개·부분 충족 1개였습니다. 마지막 문항에 명시적 재시작 요청이 있어 부분 충족을 무단 재시작이나 명백한 실패로 계산하지 않았습니다.
- 위 합성 평가의 도구 호출은 0회였고 로컬 기록상 GPT-6 Astra / High였습니다. 이번 문서 정리의 모델이나 현재 실기시험으로 소급하지 않습니다.
- 결정적 증거가 문항에 제공되고 stdin 오류 자체에 해결 단서가 있었습니다. 실제 도구 사용의 신뢰성·시간·토큰 절감 또는 신규 Skill의 전후 효과를 입증하지 않습니다. 성공 UI 관측 여러 개를 독립 시험 횟수로 더하지 않습니다.

PowerShell 인계의 JSON 배열·인수·인코딩 문제는 별도 비교 평가로 한정하여 [기존 인계 Skill](../skills/verify-powershell-handoff/SKILL.md)에 반영했습니다. 브라우저 연결 복구나 터미널 UI 조작 Skill로 확대하지 않습니다. [검증 범위](powershell-handoff.md).

## 참고할 최소 진단 순서

이는 앞선 기록에서 얻은 참고사항이며 신규 Skill의 검증된 효과가 아닙니다.

1. 요청이 연결 조회인지, 페이지 읽기인지, 행동·복구인지 먼저 구분합니다. 현재 도구가 실제 제공하는 API와 제한을 읽고 과거 ID·포트·PID를 현재 대상으로 재사용하지 않습니다.
2. 연결 없음, HTTP 접속 실패, 화면 변환, 실행 세션 입력 거부를 분리합니다. 한 계층의 오류를 다른 계층의 원인으로 단정하지 않습니다.
3. UI와 데이터가 다르면 같은 run의 원본 기록과 대조합니다. 표시된 JSON도 원본 응답이라고 가정하지 않습니다. 인증정보·전체 HAR을 공개 기록으로 올리지 않습니다.
4. 이후 입력이 필요한 명령 실행은 시작 시 stdin 유지 조건을 확인합니다. 빈 출력·세션 ID·ACK와 최종 종료 결과를 구분하고, 미확정 상태에서 중복 적용이나 광범위한 프로세스 종료로 넘어가지 않습니다.
5. 원인이 미확정이면 그대로 남깁니다. 새 실패·환경 변화·사용자 목표가 있을 때만 필요한 최소 시험을 추가하고 복구 성공과 원인 규명을 따로 판정합니다.

Windows UI용 현재 공식 지침은 터미널 애플리케이션의 UI 자동화와 이를 통한 직접·간접 명령 실행, 보안·인증·권한 설정 조작 등을 금지합니다. PowerShell 실행 도구로 승인된 명령을 수행하는 것과는 다른 경로입니다. GUI 제한을 다른 UI 경로로 우회하지 않으며 환경별 최신 지침이 우선합니다.

## 남은 리스크와 다음 기준

과거 CreateProcessWithLogonW 오류, Edge 연결 부재, 교차 세션 Stop-Process 내부 오류의 근본 원인은 미확정입니다. 현재 성공으로 과거 오류가 해결됐다고 선언하지 않습니다. Windows UI 화면 읽기·입력, CDP timeout·응답 유실, 파일 대화상자·전송, Chrome 전체 재시작 복구 및 실제 제품 시험은 이 보고의 검증 범위 밖입니다. **미실시는 실패도 PASS도 아닙니다.**

새 Skill은 반복 가능한 판단 누락이 기존 지침만으로 해결되지 않을 때만 재검토합니다. 그때 승인된 격리 조건, 고정 입력·판정 기준, 기준선과 최소 후보의 같은 입력 비교를 먼저 마련합니다. 도구 연결 결함·권한 정책·프로그램 버그라면 해당 계층의 수정으로 처리하고 Skill 효과로 대신 보고하지 않습니다.

## 출처와 검증 기준

이 보고는 로컬 연구 기록인 Edge 격리 실행 결과, Chrome·PowerShell 실제 출력 요약, 엄격 후속 평가, 좁은 기준선·독립 판정 및 현재 Windows UI 공식 API 문서와 실제 응답을 대조한 공개 요약입니다. 해당 실행의 내부 주소·PID·창 제목·기기 식별자·스크린샷·인증정보는 게시하지 않습니다. 비식별화된 요약이므로 원본 로그의 공개 독립 재현을 제공하는 자료는 아닙니다.

공식 개념 자료 확인일은 2026-10-02이며 도구 API·제한은 환경과 버전에 따라 바뀔 수 있습니다. 서버·창·브라우저 연결을 새로 읽지 않은 과거 관측은 당시 증거입니다. 이 문서 추가로 새 Skill 설치, 제품 코드·태블릿·브라우저 설정 변경은 수행하지 않습니다.
