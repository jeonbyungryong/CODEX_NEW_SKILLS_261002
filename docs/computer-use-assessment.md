# Computer Use 검토 결과와 재사용할 판단

2026-10-07 후속: [DWG 적용 점검](dwg-application-review-20261007.md)에서 실제 Windows 선택창 수용과 공식 도구 재대상을 추가 확인했습니다. 아래 10월 3일 시점의 Windows 기본 대화상자 미검증은 그때의 범위이며, 최신 DWG 한정 관측으로 모든 브라우저·파일 전송을 PASS로 바꾸지 않습니다. 신규 Skill 생성 보류는 유지합니다. 기존 지침을 읽어도 반복되는 판단 누락, 최소 후보, 동일 조건의 추가 효과가 확보되면 재검토합니다.

초기 검토 2026-10-02 KST · 파일 전송 후속 반영 2026-10-03 KST. 설치 가능한 새 Skill이나 브라우저 복구 프로그램이 아닙니다.

## 결론

Computer Use 특화 Skill은 **생성 보류**를 유지합니다. 초기 기준선에서는 추가 Skill이 필요한 명확한 반복 판단 실패를 확인하지 못했습니다. 이후 실제 파일 전송에서 표시 라벨 불일치와 확장 권한 요구를 관측하고 Chrome의 좁은 전송 성공까지 확인했지만, 기존 공식 지침에 없는 반복 판단 문제나 새 Skill의 추가 효과를 입증한 비교 시험은 아닙니다. 필요성이 없다고 입증한 것도 아닙니다. 기존 Skill 2개를 유지하며 같은 성공 시험을 새 근거 없이 반복하지 않습니다.

Skill은 반복할 판단·절차를 설명하는 지침이고, 실제 연결·인증·행동은 제공된 도구와 실행 환경에 달려 있습니다. Skill 작성이나 사용자 승인만으로 제공되지 않는 API 또는 도구의 금지 동작을 활성화하지 않습니다. [OpenAI Skills 개념](https://developers.openai.com/plugins/concepts/skills), [작성 안내](https://developers.openai.com/plugins/build/skills).

## Skill 필요성 평가와 비평

- 엄격 권한·포트 평가: 시나리오 2종, 새 문맥 6개, 응답 13개. 초기 권한 응답 5개는 독립 검토에서 충족했습니다. 후속 응답 모두를 독립 검증한 것은 아니며 13개 독립 실시험으로 세지 않습니다.
- 표시 변환·stdin·지연 종료의 좁은 후속 평가: 새 문맥 3개, 각각 1회. 독립 판정은 충족 2개·부분 충족 1개였습니다. 마지막 문항에 명시적 재시작 요청이 있어 부분 충족을 무단 재시작이나 명백한 실패로 계산하지 않았습니다.
- 위 합성 평가의 도구 호출은 0회였고 로컬 기록상 GPT-6 Astra / High였습니다. 이번 문서 정리의 모델이나 현재 실기시험으로 소급하지 않습니다.
- 결정적 증거가 문항에 제공되고 stdin 오류 자체에 해결 단서가 있었습니다. 실제 도구 사용의 신뢰성·시간·토큰 절감 또는 신규 Skill의 전후 효과를 입증하지 않습니다. 성공 UI 관측 여러 개를 독립 시험 횟수로 더하지 않습니다.

PowerShell 인계의 JSON 배열·인수·인코딩 문제는 별도 비교 평가로 한정하여 [기존 인계 Skill](../skills/verify-powershell-handoff/SKILL.md)에 반영했습니다. 브라우저 연결 복구나 터미널 UI 조작 Skill로 확대하지 않습니다. [검증 범위](powershell-handoff.md).

## 참고할 최소 진단 순서

이는 앞선 기록에서 얻은 참고사항이며 신규 Skill의 검증된 효과가 아닙니다.

1. 요청이 연결 조회인지, 페이지 읽기인지, 행동·복구인지 먼저 구분합니다. 현재 도구가 실제 제공하는 API와 제한을 읽고 과거 ID·포트·PID를 현재 대상으로 재사용하지 않습니다.
2. 연결 없음, HTTP 접속 실패, 화면 변환, 실행 세션 입력 거부를 분리합니다. 한 계층의 오류를 다른 계층의 원인으로 단정하지 않습니다.
3. UI와 데이터가 다르면 같은 run의 원본 기록과 대조합니다. 표시된 JSON도 원본 응답이라고 가정하지 않습니다. 인증정보·전체 HAR을 공개 기록으로 올리지 않습니다.
4. 이후 입력이 필요한 명령 실행은 시작 시 stdin 유지 조건을 확인합니다. 빈 출력·세션 ID·ACK와 최종 종료 결과를 구분하고, 미확정 상태에서 중복 적용이나 광범위한 프로세스 종료로 넘어가지 않습니다.
5. 원인이 미확정이면 그대로 남깁니다. 새 실패·환경 변화·사용자 목표가 있을 때만 필요한 최소 시험을 추가하고 복구 성공과 원인 규명을 따로 판정합니다.

Windows UI용 현재 공식 지침은 터미널 애플리케이션의 UI 자동화와 이를 통한 직접·간접 명령 실행, 보안·인증·권한 설정 조작 등을 금지합니다. PowerShell 실행 도구로 승인된 명령을 수행하는 것과는 다른 경로입니다. GUI 제한을 다른 UI 경로로 우회하지 않으며 환경별 최신 지침이 우선합니다.

## 남은 리스크와 다음 기준

과거 CreateProcessWithLogonW 오류, Edge 연결 부재, 교차 세션 Stop-Process 내부 오류의 근본 원인은 미확정입니다. 후속 전송 성공으로 과거 오류가 해결됐다고 선언하지 않습니다. Windows 기본 파일 대화상자 조작, Windows UI 경로의 브라우저 URL 판별 복구, CDP timeout·응답 유실, Edge 파일 전송, Chrome 전체 재시작 복구 및 실제 제품 시험은 이 보고에서 입증하지 않았습니다. **미실시는 실패도 PASS도 아닙니다.** 내장 브라우저와 Chrome 공식 확장 경로의 작은 파일 전송만 아래 범위로 확인했습니다.

새 Skill은 반복 가능한 판단 누락이 기존 지침만으로 해결되지 않을 때만 재검토합니다. 그때 승인된 격리 조건, 고정 입력·판정 기준, 기준선과 최소 후보의 같은 입력 비교를 먼저 마련합니다. 도구 연결 결함·권한 정책·프로그램 버그라면 해당 계층의 수정으로 처리하고 Skill 효과로 대신 보고하지 않습니다.

## 2026-10-03 파일 전송 후속 검토

### 확인된 사실과 증거 범위

회사·제품 자료가 아닌 134바이트 합성 텍스트 파일로 시험했습니다. 내장 브라우저 완료 run 1개, Chrome 권한 차단 run 1개, 사용자 설정 변경 보고 후 Chrome 완료 run 1개를 구분합니다. 한 run 안의 여러 UI 관측이나 재대상을 별도의 독립 시험 횟수로 더하지 않습니다. 실행 모델은 GPT-6.1 Sol / High였고 override하지 않았습니다.

| 경계 | 관측 | 판정·제한 |
| --- | --- | --- |
| 내장 브라우저 전송 | 공식 파일 선택·업로드 1회·다운로드, 두 파일의 크기·SHA-256 일치 | 작은 합성 파일 1회 PASS; Chrome·Edge로 전이하지 않음 |
| Chrome 연결·접속 | 공식 확장 연결 목록과 시험 페이지 접속 확인 | PASS; 연결이 나타난 원인은 미확정 |
| Chrome 첫 파일 선택 | 파일 선택 대기 시간 초과와 처리되지 않은 Promise 거부로 세션 초기화 | 실패한 시도; 화면이 번역되어 기존 영문 라벨 0개·현재 한글 라벨 1개 확인 |
| Chrome 파일 지정 | 현재 라벨로 chooser 이벤트는 도착; setFiles가 파일 URL 접근 설정 필요를 명시 | 권한 차단 run의 업로드 횟수 0; 임의로 권한 변경하지 않음 |
| 사용자 설정 변경 후 | 새 run에서 파일 지정·업로드 1회·다운로드, 디스크 전체 바이트·크기·SHA-256 일치 | 좁은 전송 흐름 PASS; 설정 완료 보고만으로 판정하지 않음 |
| 표시 변환 | 파일 이름 표시·JSON 키도 번역됨; 서버 영수증과 실제 파일은 별도 대조 | 표시를 원본 데이터나 손상 증거로 간주하지 않음 |
| 마지막 서버 정리 | listener 접속 거부 뒤에도 소유 Node 프로세스가 남음; 실행 경로·시작 시각 확인 후 해당 프로세스만 강제 종료 | 정리 완료이나 정상 종료 PASS는 아님; 종료 지연의 원인 미확정 |

첫 Chrome 시도의 오래된 라벨 문제와 이후 명시적인 파일 접근 권한 오류는 서로 다른 경계입니다. 전자는 현재 화면으로 대상을 다시 선택한 뒤 chooser 이벤트가 도착했고, 후자는 사용자가 직접 설정했다고 보고한 다음 run에서 파일 지정이 성공했습니다. 이것만으로 Windows UI의 URL 판별 실패나 모든 브라우저 연결 문제가 해결됐다고 결론 내리지 않습니다.

공식 chooser API는 Windows 기본 Open 대화상자의 좌표 조작 시험이 아닙니다. 합성 서버의 계약 시험 통과도 실제 브라우저 조작의 대체 증거가 아닙니다. 파일 선택·지정의 일부 호출이 요청 timeout보다 오래 반환됐지만 도구·전송 시간이 섞인 단일 관측이므로 페이지 성능, 브라우저 우열, 개선률이나 원인을 추정하지 않습니다.

### 재사용할 판단과 추가 Skill 비평

- **실제 API를 먼저 확인:** 공식 브라우저 연결과 Windows 창 목록은 다른 채널이다. 하나의 URL 판별 중단을 다른 채널에서 우회할 권한으로 해석하지 않는다. 새 턴에서 유효한 공식 연결이 제공된 경우에만 그 경로로 새 시험을 한다.
- **현재 화면으로 재대상:** 번역·화면 변경 후 라벨과 상태를 다시 관측한다. 확인된 실제 파일 입력처럼 번역에 영향받지 않는 대상이 있으면 사용할 수 있지만 보이지 않는 요소나 API는 추측하지 않는다.
- **선택과 전송 분리:** chooser 도착, 파일 지정, 업로드 수락, 다운로드 경로, 실제 디스크 바이트를 구분한다. 대기 Promise의 거부를 생성 직후 처리해 미처리 오류가 다음 진단 증거를 잃게 하지 않는다.
- **명시적 권한 오류는 최소 인계:** 필요한 설정과 대상 확장을 정확히 안내하고, 사용자가 직접 완료한 뒤 실제 동작을 재검증한다. 전체 CDP·모든 사이트 허용으로 확장하거나 보안 설정을 자동화하지 않는다.
- **정리는 독립 판정:** 포트 닫힘과 프로세스 종료를 별도로 확인한다. 강제 종료가 필요하면 현재 실행 파일·시작 시각 등 소유 증거를 확인하고, 정상 종료로 바꿔 기록하지 않는다.

이는 실제 실패·복귀에서 추출한 참고 절차이지, 새 Skill의 효과를 증명한 결과가 아닙니다. 현재 공식 파일 업로드 지침은 chooser 흐름과 권한 오류 인계를 이미 제공하고, 브라우저 지침은 현재 상태 재관측을 요구합니다. 기존 PowerShell 인계 Skill을 브라우저 복구까지 늘리거나 장치 조율 Skill에 특정 브라우저 설정을 넣으면 사용 조건이 흐려집니다. 새 특화 Skill은 아직 만들지 않습니다.

### 실행안과 남은 검증

이번 후속으로 문서만 갱신하며 기존 Skill 본문·설치 상태·제품·브라우저 설정은 변경하지 않습니다. 사용자 설정 변경은 앞선 실행의 사용자 보고이고 이 문서 작업이 수행한 변경이 아닙니다. 원본 실행 기록과 실패 표본은 로컬에 보존하며 공개 문서에는 내부 경로·포트·PID·연결 ID·스크린샷을 넣지 않습니다.

## 2026-10-07 로컬 접속·브라우저 읽기 후속 검토

설치형 Computer Use 신규 Skill은 생성 보류를 유지합니다. 기존 지침으로도 제한된 기준선을 충족했으며, 새 Skill의 추가 효과는 검증하지 않았습니다. 다음은 기존 평가 문서에 보강한 비식별 후속 근거입니다.

### 확인된 사실

- 합성 답변 평가, 제품과 분리된 실제 HTTP 동작, 반복 실패 이력 입력을 명확히 한 새 문맥 검증을 구분했습니다. 정상 포트 이전과 명시적 접근 거부의 우회를 혼동하지 않았고, 실제 응답 계층 분리와 실패 후 독립 파일 검증을 관측했습니다. 원본 불일치는 통과로 바꾸지 않았습니다.
- 자체 작성 data 형식 시험 페이지를 새 탭에 여는 시도는 URL protocol 정책으로 거부됐습니다. 해당 도구 응답은 HTTP·HTTPS만 허용한다고 설명했습니다. 이는 그 환경의 시험 주소 형식 제한이지 포트나 제품 연결 실패의 증거가 아닙니다. 모든 HTTP·HTTPS 주소가 허용된다는 뜻도 아닙니다.
- 거부된 페이지를 다른 브라우저·포트·도구로 대행하지 않았습니다. 실패 중 생성된 자기 빈 시험 탭이 남아 있어, 그것만 정리한 뒤 기존 탭 식별자 집합을 대조했습니다.
