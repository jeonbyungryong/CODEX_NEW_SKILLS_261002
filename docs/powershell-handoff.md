# PowerShell 인계 Skill: 분석·검증·제한 채택

2026-10-02 · v0.2. 결론은 `verify-powershell-handoff`를 **Windows 파일 검증 스크립트 인계용으로 제한 채택**한다는 것이다. Computer Use 연결 복구 Skill로 확대하지 않는다.

## 조사에서 확인한 문제

실제 프로젝트 인계에는 PowerShell 버전 차이, Git staged 공백·commit 신원·worktree 바이트, 빌드 초기화·메모리·assertion, 원격 동시 변경이 섞여 있었다. 같은 오류 한 줄로 인증·포트·코드 오류라고 단정할 수 없었다. 역사적 분류만으로 신규 Skill 필요성을 결정하지 않고 가상 기준선을 먼저 조사했다.

최초 3종 단회 선별은 이전 GPT-6 Astra / High에서 수행했다. H1 대상 셸 배열 문제는 놓쳤지만 H2 로컬 Git 단계와 H3 부분 완료·원격 가드는 충족했다. 이 단회 결과를 현재 모델의 반복 비교 수치에 합치지 않았다.

## 동일 입력 비교

후속 실험은 GPT-6.1 Sol / High, 모델·추론 override 없음, 새 문맥, 평가 agent의 실제 도구 호출 0회였다. 기준과 생성 조건을 먼저 고정했다. H1은 UTF-8 3개 JSON 레코드와 한글·공백 인수, PowerShell 7 작성자/5.1 수신자, 구문·해시만 확인된 인계 사례다.

| 기준 | 적용 전 | 고정 후보 적용 후 |
| --- | --- | --- |
| READY 보류와 증거 범위 구분 | 5/5 | 5/5 |
| 알려진 5.1 배열 결함 해결 또는 구체적 구조 시험 | 0/5 | 5/5 |
| 네이티브 인수 경계 보존 | 5/5 | 5/5 |
| 인코딩·즉시 종료 코드 확인, 미실행 주장 금지 | 5/5 | 5/5 |

적용 전 모두 수정 코드에 직접 파이프라인을 둘러싼 `@()`를 남겼다. 실제 5.1에서 3개 배열의 외부 Count가 1이 되는 메커니즘을 재현했다. 후보 적용 후 모두 파싱과 배열 구성을 분리하고 Count 3을 유지했다. “전체 스크립트를 나중에 실행”이라는 일반 지시는 이미 남아 있는 구체적 결함의 해결로 채점하지 않았다.

별도 채점자에게 응답 순서를 섞고 그룹명을 숨겼다. 실제 메커니즘 증거와 사전 기준만 제공해 같은 결론을 얻었다. 안내를 받았다는 응답 표현 때문에 완전한 맹검은 아니다. 부모도 원문·기준을 대조했다. 독립 검토는 helper 출력 디코딩 표현의 모호성과 한 응답의 해시 일치→바이트 동일성 표현을 지적했다. 해시 일치는 바이트 동일성의 근거이지 직접 비교 증거라고 확대하지 않는다. 이 지적을 숨기거나 새로운 실제 실패라고 과장하지 않았다.

## 추가 사례와 실제 실행

후보 해시 SHA256 `4619EEDF5AA58DF0F80BAA234B650660F076EEC52C9AAA2A6B1E235177A12B93`를 고정했고 응답에 맞춰 본문을 재조정하지 않았다.

| 구분 | 관측 |
| --- | --- |
| H2 로컬 Git 인계, 1회 | 신원·공백·서명 파일 바이트와 실제 로컬 단계 시험을 구분, 진단용 push 없음 |
| H3 복사 완료·원격 변경, 1회 | 복사 재실행/가드 완화 없이 최신 원격 검토와 증거 기반 완료 제안 |
| J0 빈 배열·null, 1회 | 0개는 유효, null 1개는 보존 후 스키마 거부 |
| J1 단일 항목, 1회 | Count 1만으로 여러 항목 호환성이 증명되지 않음; 형태·필드 검사 |
| PowerShell 5.1.26100.9444 | 기초 17개 통과, 직접 컬렉션 Count 1 |
| PowerShell 7.6.5 | 기초 17개 통과, 직접 컬렉션 Count 3 |

실제 기초 시험은 빈/단일/3개/null/중첩 보존, 비배열·잘못된 JSON 거부, 할당 후 일반 배열 구조, Python 합성 도우미의 인수 4개·한글/공백·종료 0/7·UTF-8 로그와 실패 시 성공 도달 차단이다. 실제 파일 검증 도우미나 전체 운영 진입점은 실행하지 않았다. 사용자 PowerShell 업그레이드·패키지 설치·전역 설정·기기 조작은 하지 않았다.

## 채택 범위와 비평

- 지침은 대상 셸에서 데이터 형태와 실제 호출을 검증하도록 돕는다. 자동 복구 프로그램이 아니다.
- 빈 배열/null을 일반 할당 패턴으로 뭉개지 않도록 별도 속성 보존 예를 제공한다. JSON 형태와 레코드 스키마는 서로 다른 검사다.
- 구문·원본 해시·다른 wrapper의 ASCII 성공을 전체 인계 성공으로 이월하지 않는다.
- 일반 Git 배포·Gradle 캐시 처방·브라우저 포트·권한 우회는 범위 밖이다.
- 모델 한 개·주 사례 한 개·각 5회다. 정답 방법을 직접 제공한 효과이며 일반화·통계적 우월성·실제 시간/토큰 절감은 입증하지 않았다.
- 추가 사례는 각 1회 의미 검토이며 실사용 시험이 아니다. 다양한 도우미 인수 인용 규칙과 전체 Skill 상호작용은 미검증이다.
- 구조는 제한된 frontmatter/name/description 읽기 검사로 확인했다. 공식 `quick_validate.py`는 PyYAML 부재로 성공 실행하지 못했다. 공식 검증기 PASS로 기록하지 않는다.
- 전역 설치·자동 선택·브라우저/태블릿 효과는 NOT_RUN이다. 사용 가능 목록에 설치되어 나타나는지는 별도로 확인해야 한다.

## 출처와 검증 기준

최종 읽기 전용 독립 검토에서 Critical/Important 병합 차단 항목은 없었다. README의 ‘배열 누락’ 표현을 실제 데이터 유실로 오해하지 않도록 ‘결함을 놓친 검토 응답’으로 명확히 했다. 후보 Skill 본문은 바꾸지 않았다. 원 실행 trace·게시 리허설·실제 원격 완료 확인은 부모 작업자가 담당하며, 최종 검토자가 그 모든 실행을 별도 인증한 것은 아니다.

[사전 프로토콜·원문·별도 채점·수치·재현 도구](../evals/powershell-handoff/README.md)가 이번 관측의 근거다. 과거 오류를 정답 문구로 복사하지 않고 다른 작은 입력으로 비교했다. 설치·사용법은 [사용 안내](usage.md), 실제 지침은 [SKILL.md](../skills/verify-powershell-handoff/SKILL.md)를 따른다. 기존 실기 협업 Skill과 원본 평가 자료는 변경하지 않는다.
