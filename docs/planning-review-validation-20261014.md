# 명세와 개발 검토 스킬의 게시 범위

2026-10-14에 `specify-failure-recovery`와 `review-release-evidence`를 추가한다. 두 파일은 기존 프로젝트 회고에서 보완하고 독립 적용한 지침이다. 이번 게시에서는 검증된 본문을 그대로 옮기고 [단계별 사용 안내](planning-review-skills.md)를 작성했다.

## 저장소 규칙과 중복 검토

게시 전 `main` 기준은 `0aab0b70f9ca6e053b7457b210d2f7c4234fcbfe`였다. 저장소에는 별도 `AGENTS.md`, `CONTRIBUTING` 또는 CI workflow가 없었으며, README의 공개 자료·보존 원칙과 `docs/design.md`의 최소 범위·검증 수준 구분을 적용했다. 조회 시 활성 repository ruleset은 없었고 `main`은 보호 브랜치가 아니었다. 이는 조회 당시 상태이며 향후 게시 권한이나 규칙을 고정하지 않는다.

- 두 이름은 기존 세 스킬에 없었다. 오류 계약과 후보별 근거 판정은 실기 조율·PowerShell 인계·native 복구의 실행 절차를 복제하지 않는다.
- 기존 설계의 보류 후보 `scope-to-acceptance`를 전면적인 개발 관리 도구로 되살리지 않는다. 새 릴리즈 지침은 원본·후보·미검증·종료 판정의 좁은 참고서이며 효과 입증과 구분한다.
- `skills/`에는 두 단일 지침 파일만 추가한다. 상세 사용 예와 게시 검증은 `docs/`에 두고 README·사용 안내에서 연결한다.
- 원본 회사 자료·장치 로그·APK·개인 PC 절대 경로·키·인증정보·임시 검사 패키지는 포함하지 않는다. 공개 예시는 일반화된 상황이다.
- 기존 세 스킬과 이전 평가 자료는 수정하지 않는다. 강제 push나 이력 교체를 하지 않는다. 기존 라이선스 미지정 상태도 유지한다.

## 기존 적용 시험에서 확인한 내용

보완 전 오류 계약 적용 응답은 정책이 미정인데 재시도 시간과 횟수를 본문에 채우고 끝에서만 제안값이라고 설명했다. 결정 담당·시점·그 전 진행 범위, 항목별 제안 표시를 보완했다. 초기 요구에 있던 PIN 재시도는 구현·해제 시험 누락으로 바로잡았으며, 모든 오류가 같은 UI에서 해제돼야 한다는 과잉 일반화도 문서에서 제거했다.

수정 후 새 문맥의 독립 적용자는 두 파일만 읽고 다음을 판단했다.

| 가상 적용 사례 | 관측된 판단 |
| --- | --- |
| 장비를 제공할 수 없는 완료 제품의 회고 | 기존 코드·로그와 교훈으로 종료. 미해결 결정을 바꾸지 않는 에뮬레이터·새 스킬·추가 리뷰는 수행하지 않음 |
| 재시도·인증 정책과 담당이 미정인 웹 메모 명세 | 임의 수치를 넣지 않음. 결정 역할·시점을 미정으로 기록하고 보존·상태 계약까지 진행 |
| 재시작이 승인된 오류 복구 | 과거 PIN 사례의 같은 UI 해제를 강제하지 않고 재시작 후 조작 가능 상태를 기준으로 삼음 |

작은 계산기에는 두 문장의 발생·해제 명세만 적용한 별도 사례도 있었다. 이전 기준 응답은 스킬 없이도 핵심 안전 판단을 잘 구분했으므로 스킬이 모든 판단을 개선했다고 주장하지 않는다. 무작위 반복 A/B, 시간·비용 절감, 자동 선택률, 다른 PC의 실제 설치·제품 성공은 입증하지 않았다. 이 문서는 비식별 요약이며 회사 원본이나 전체 실행 trace를 공개하는 증거 패키지가 아니다.

## 본문 식별과 로컬 적용

게시 파일의 UTF-8 원본 SHA256은 다음과 같다. Git 체크아웃의 줄바꿈 변환 여부를 구분해 비교한다.

- `skills/specify-failure-recovery/SKILL.md`: `486607BA543AA995A7BA2D08D6CAC92387161D2E2A6925046171A2ABD84A8CA9`
- `skills/review-release-evidence/SKILL.md`: `2F980442585BB1CF3A1169FF9BA8DCD20D0762E72A3022114B4176D9BFC29988`

이 버전은 게시 전 공식 `quick_validate.py` 검사에서 두 파일 모두 exit 0이었고, 개인 설치본·보관본의 일치와 후속 요청의 사용 가능 목록을 확인했다. 이번 게시에서는 파일 복사 후 해시와 이름 중복·참조·공개 범위·Git 차이를 확인한다. 형식 통과와 파일 일치는 전체 행동 정확성이나 제품 수용을 대신하지 않는다.

다른 PC에서는 [설치 요청 예시](planning-review-skills.md#다른-pc와-프로젝트에-설치)로 필요한 두 폴더만 설치한다. 같은 이름이 있으면 동일본은 건너뛰고 변경본은 비교한다. 스킬의 필요성이 없는 프로젝트에 일괄 적용하지 않는다.
