# 로컬 접속 진단·작업 지속 체크리스트

2026-10-08 · 명시적으로 읽는 참고 문서. SKILL.md가 아니며 설치·자동 선택·권한 부여 기능이 없습니다. 현재 도구의 공식 API/오류와 사용자의 승인 범위를 먼저 확인하세요.

## 한 계층의 실패를 다른 문제로 바꾸지 않기

| 실제 관측 | 의미와 최소 다음 행동 |
| --- | --- |
| 서버 bind가 EADDRINUSE | 해당 listener와 서비스 소유권을 읽기 전용으로 확인. 승인된 자기 개발 서비스의 포트 이전은 가능; 남의 프로세스를 포트만 보고 종료하지 않음 |
| 브라우저 연결/API가 없음 | 그 채널 사용 불가. 서버나 제품 전체 장애라고 단정하지 않음. 승인된 독립 작업·수동 인계로 분리 |
| saved user permission 또는 명시적 정책 거부 | 같은 보호 행위를 포트·브라우저·셸·직접 API로 대행하지 않음. 소유자 승인만으로 도구 제한이 바뀌지 않음. 적용되는 안내가 있다면 필요한 사용자 설정 변경을 정확히 인계 |
| 지원하지 않는 URL 형식 | 포트 고장 근거가 아님. 형식 지원 안내와 명시적 정책 거부를 구분. 도구가 허용하는 정상 주소 지정은 일률적으로 금지하지 않되, 오류가 금지한 행위를 재포장하지 않음 |
| root HTTP 응답 | 그 요청의 응답 근거일 뿐. 현재 배치·인증·편집·전송 성공은 각 계약/응답으로 확인 |
| 인증 실패/편집 잠금 | 실제 API 계약과 응답 내용으로 판정. 허가 없는 로그인 우회나 타 편집자 종료 금지; 잠금 응답 자체는 무응답이 아님 |

## 정상 포트 이전 조건

사용자가 서비스 변경을 승인했고, 목적이 도구 차단 우회가 아닌 실제 충돌·운영 변경이어야 합니다. 현재 listener/서비스의 소유권을 확인하고 자기 서비스만 다룹니다. 서버 listen 값, 클라이언트 base URL, 설정·환경·스크립트·시험 명령의 참조를 함께 검토하세요. 준비된 새 포트의 bind/클라이언트 동작을 확인하고 기존 서비스 보존과 원복 방법을 기록합니다. 제품과 별개의 synthetic 서비스 시험을 제품 포트 이전 성공으로 보고하지 마세요.

## 반복 종료와 일정 관리

동일 실패·설정 무변경·새 근거 없음이면 같은 재시도를 늘리지 않습니다. 어떤 관측이 있어야 재개할지 남기고 이미 승인된 독립 파일 검사·코드 검토·문서 인계를 계속합니다. 사용자 소유 시스템이라는 이유로 모든 경로가 허용된다고도, 한 도구가 막혔다는 이유로 개발 전체가 불가능하다고도 판단하지 않습니다.

안전 조건을 만드는 비용이 시험 목적보다 커지면 더 작은 오프라인 사례·사람의 조작·미검증 보류를 제시합니다. 마감은 범위를 줄이는 근거이지 PASS 기준이나 권한을 낮추는 근거가 아닙니다. 정리는 자기 자원만, 실제 종료 근거로 별도 판정합니다.

## 기록할 최소 정보

목표/승인 범위, 실행 계층과 실제 오류, 환경 변화 유무, 수행·미실시, 원인 추정의 한계, 자기 변경·정리 상태, 다음 재개 조건을 남깁니다. 원시 인증정보·내부 주소·HAR·장치/프로세스 식별정보는 공개 자료에 넣지 마세요. 두 번의 실패 관측만으로 그 사이의 연속 단절이나 배터리 원인을 증명하지 않습니다.

이 참고사항은 [검증 마감 보고](validation-closeout-20261008.md)와 [역사 평가](computer-use-assessment.md)의 범위 안에서만 근거를 가집니다. 새 Skill의 추가 효과, 실제 과거 장애 복구 또는 장기 안정성은 미입증입니다.
